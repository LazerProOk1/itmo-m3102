title: Проверь себя: инверсии и сортировки
description: Что такое инверсия, сколько их бывает, связь со вставками и процедура слияния.

? Что такое инверсия массива $a$?
- [x] Пара индексов $i < j$, для которой $a[i] > a[j]$ :: Элементы стоят «не в том порядке» для сортировки по возрастанию.
- [ ] Пара соседних равных элементов :: Равные элементы инверсию не образуют.
- [ ] Индекс, на котором массив меняет направление :: Инверсия — это пара, а не одна позиция.

? Сколько инверсий в массиве $[3, 1, 2]$? Введите число.
= 2
correct: Пары $(3, 1)$ и $(3, 2)$; пара $(1, 2)$ стоит правильно.
wrong: Переберите пары $i < j$: $(3,1)$ — инверсия, $(3,2)$ — инверсия, $(1,2)$ — нет. Итого 2.

? Сколько инверсий в массиве из $n$ элементов в худшем случае и когда он достигается?
- [x] $\frac{n(n-1)}{2}$ — массив отсортирован в обратном порядке :: Тогда инверсию образует каждая пара $i < j$.
- [ ] $n - 1$ — массив в обратном порядке :: Это только соседние пары, а инверсии бывают и между далёкими элементами.
- [ ] $n^2$ — любой массив :: Пар $i < j$ всего $\binom{n}{2}$, больше инверсий не бывает.

? Как время сортировки вставками связано с числом инверсий?
- [x] $T(n) = \Theta(n + Inv(a))$ :: Каждый сдвиг устраняет ровно одну инверсию.
- [ ] $T(n) = \Theta(n \log n)$ всегда :: Время зависит от исходной неупорядоченности.
- [ ] $T(n) = \Theta(Inv(a)^2)$ :: Зависимость от числа инверсий линейная.
explain: На почти отсортированном массиве инверсий мало — вставки работают почти за $O(n)$.

? В процедуре `merge` элементы под `it1` и `it2` равны. Что делают?
- [x] Пишут элемент из первого подмассива и сдвигают `it1` :: Так сохраняется устойчивость.
- [ ] Пишут элемент из второго подмассива :: Тогда равные элементы поменяются местами.
- [ ] Пишут оба и сдвигают оба указателя :: Так тоже можно, но процедура из практики берёт первым левый.

? Что делается после основного цикла слияния?
- [x] Дописываются оставшиеся элементы того подмассива, который не закончился :: Они уже отсортированы и все не меньше записанных.
- [x] Буфер копируется обратно в исходный массив :: Результат слияния собирается во временном буфере.
- [ ] Буфер ещё раз сортируется :: Он уже отсортирован.

? Когда рекурсия mergesort останавливается?
- [ ] Когда диапазон делится на два без остатка :: Деление не связано с остановкой.
- [x] Когда в диапазоне один элемент или ни одного :: Такой диапазон уже отсортирован.
- [ ] Когда глубина достигла $\log_2 n$ :: Это следствие, а не условие остановки.
