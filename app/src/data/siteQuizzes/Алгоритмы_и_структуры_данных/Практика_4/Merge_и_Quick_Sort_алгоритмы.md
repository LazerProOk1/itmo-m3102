title: Проверь себя: итеративный Merge Sort и quickSort
description: Проходы с размером блока $s$, обмен буферов, схемы разбиения Ломуто и Хоара.

? С какого размера блока $s$ начинается итеративный Merge Sort и как он меняется?
- [x] С $s = 1$, на каждом проходе удваивается :: Блоки из одного элемента уже отсортированы.
- [ ] С $s = 2$, на каждом проходе удваивается :: Тогда одиночные блоки никогда не сольются между собой — частая ошибка.
- [ ] С $s = n/2$, на каждом проходе уменьшается вдвое :: Так спускается рекурсия, а итеративная версия идёт снизу вверх.

? На проходе левый блок пары начинается с $i$, а $i + s \ge n$. Что делать?
- [ ] Ничего: элементы и так в массиве :: После `swap(arr, buf)` «настоящим» станет `buf`, и они потеряются.
- [x] Пропустить слияние, но перенести элементы блока в буфер :: Блок без пары остаётся как есть до следующего прохода.
- [ ] Слить блок с пустым правым и удвоить $s$ :: $s$ удваивается после всего прохода, а не из-за одного блока.

? Почему `swap(arr, buf)` работает за $O(1)$?
- [x] Меняются местами только указатели на массивы, а не их содержимое :: Копирования элементов нет.
- [ ] Потому что массивы маленькие :: Размер не важен — копирования нет вообще.
- [ ] Потому что меняется только первый элемент :: Меняются роли массивов целиком.

? Массив $[2, 5, 3, 52, 1, -1448, 993]$. Как он выглядит после прохода $s = 1$?
- [x] $[2, 5, 3, 52, -1448, 1, 993]$ :: Пары сливаются попарно, 993 остаётся без пары.
- [ ] $[2, 3, 5, 52, -1448, 1, 993]$ :: Это уже после прохода $s = 2$.
- [ ] $[-1448, 1, 2, 3, 5, 52, 993]$ :: Это итог после $s = 4$.

? Разбиение по Ломуто массива $[8, 3, 7, 1, 9, 2, 5]$, опорный — последний элемент 5. На какой индекс (с нуля) встанет 5? Введите число.
= 3
correct: Меньше 5 элементы 3, 1, 2 — они займут индексы 0–2, опорный встанет на индекс 3: $[3, 1, 2, 5, 9, 7, 8]$.
wrong: Слева окажутся все элементы меньше 5 — это 3, 1, 2. Значит, опорный 5 встанет сразу за ними, на индекс 3: $[3, 1, 2, 5, 9, 7, 8]$.

? Чем результат разбиения Хоара отличается от разбиения Ломуто?
- [x] Хоар возвращает границу между частями, а не место опорного; у Ломуто опорный сразу на окончательном месте :: Поэтому рекурсия по Хоару идёт по $[lo; p]$ и $[p+1; hi]$.
- [ ] Хоар сортирует отрезок целиком за один проход :: Это только разбиение.
- [ ] Ничем, отличаются только названия :: Указатели и результат у схем разные.

? Почему в записи схемы Хоара опорный берут первым элементом $a[lo]$?
- [x] С последним элементом $a[hi]$ рекурсия может зациклиться на отрезках, которые не уменьшаются :: Граница может оказаться в самом конце.
- [ ] Так быстрее в среднем :: Скорость тут ни при чём, речь о корректности.
- [ ] Первый элемент всегда медиана :: Нет, опорный может быть любым значением.

? Какие указатели использует схема Ломуто?
- [x] Сканер $j$ идёт слева направо, $i$ отмечает границу «меньших опорного» :: Один проход по отрезку.
- [ ] Два указателя идут навстречу друг другу с концов :: Это схема Хоара.
- [ ] Один указатель, который идёт справа налево :: Сканер у Ломуто движется слева направо.
