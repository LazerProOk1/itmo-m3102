# Инверсии в массиве. Сортировка вставками и сортировка слиянием

## Инверсии в массиве

:::meaning
**Инверсия** массива $a$ — это пара индексов $i < j$, для которой элементы стоят «не в том порядке» относительно возрастающей сортировки, то есть $a[i] > a[j]$. Рассматриваются все пары индексов $i < j$ (в конспекте это записано сокращённо как $\forall\, i < j$).
:::

Обозначения:
- $Inv(a)$ — общее число инверсий во всём массиве $a$ (сумма по всем парам $i<j$, для которых $a[i]>a[j]$);
- $Inv_{i_1}$, $Inv_{i_2}$ — число инверсий, связанных с конкретным элементом $a[i]$.

:::warning
В исходном конспекте не до конца раскрыто, чем именно различаются обозначения $Inv_{i_1}$ и $Inv_{i_2}$ — зафиксированы только сами обозначения, без пояснения. Далее эти величины упоминаются в общем смысле «число инверсий, связанных с элементом $a[i]$», как и указано в конспекте: «это инверсия массива и инверсии для элементов».
:::

### Лучший и худший случаи

:::remember
- **Лучший случай:** $0$ инверсий — достигается, если массив уже отсортирован.
- **Худший случай:** $\dfrac{n(n-1)}{2}$ инверсий, что по порядку роста составляет $\Theta(n^2)$ — достигается, если массив отсортирован в обратном порядке.
:::

В худшем случае абсолютно каждая пара индексов $i<j$ образует инверсию. Число всех таких пар для массива из $n$ элементов равно числу сочетаний $\binom{n}{2} = \dfrac{n(n-1)}{2}$ — отсюда и берётся эта формула.

### Компаратор

Компаратор — функция сравнения двух элементов массива, отвечающая на вопрос, находятся ли элементы $a[i]$ и $a[j]$ в инверсии.

$$
\text{comparator}(a[i], a[j]) =
\begin{cases}
\text{yes}, & a[i] < a[j] \\
\text{no}, & \text{иначе}
\end{cases}
$$

## Связь с сортировкой вставками

:::note
В конспекте этот момент отмечен пометкой «тут идёт описание сортировки вставками» — сам алгоритм подробно не расписан, зафиксирована только его связь с числом инверсий.
:::

Ключевое наблюдение: при сортировке вставками элемент $a[i]$ в процессе работы алгоритма сдвигается ровно столько раз, сколько инверсий с его участием было у него в исходном массиве.

:::formula
$$
T(n) = \Theta(n + Inv(a))
$$
:::

:::meaning
Время работы сортировки вставками зависит не только от размера массива $n$, но и от того, насколько массив изначально неупорядочен, то есть от общего числа инверсий $Inv(a)$. Чем меньше инверсий, тем быстрее отработает сортировка; в пределе, когда массив уже отсортирован ($Inv(a)=0$), время работы линейно — $\Theta(n)$.
:::

## Сортировка слиянием (mergesort)

:::note
Этот раздел в конспекте отмечен пометкой «тут идёт описание mergesort» — зафиксирован только псевдокод процедуры слияния (merge) двух уже отсортированных частей массива, без общего описания рекурсивной схемы mergesort.
:::

Обозначения (указатели/итераторы):
- `arr1`, `arr1_end` — начало и граница конца первого подмассива;
- `arr2`, `arr2_end` — начало и граница конца второго подмассива;
- `it1` — текущий указатель на первый подмассив, изначально равен `arr1`;
- `it2` — текущий указатель на второй подмассив, изначально равен `arr2`;
- `itr` — указатель на буфер, куда записывается результат слияния.

```cpp
arr1, arr1_end, arr2, arr2_end
it1 = arr1
it2 = arr2
itr = buffer

while it1 < arr1_end and it2 < arr2_end:
    if it1 < it2:
        itr = it1; ++it1
    else if it2 < it1:
        itr = it2; ++it2
    else:
        itr = it1; ++it1

while it1 < arr1_end:
    itr = it1; it1++; itr++

while it2 < arr2_end:
    itr = it2; it2++; itr++
...
```

:::example
Разберём псевдокод пошагово:

1. Пока оба указателя не дошли до конца своих подмассивов (`it1 < arr1_end and it2 < arr2_end`), сравниваются элементы, на которые они указывают:
   - если элемент, на который указывает `it1`, меньше элемента `it2` — он записывается в буфер (`itr = it1`), после чего `it1` сдвигается вперёд (`++it1`);
   - если, наоборот, меньше элемент `it2` — записывается он, и сдвигается `it2`;
   - если элементы равны — в буфер записывается элемент из первого подмассива (`it1`), и сдвигается `it1`.
2. Когда основной цикл заканчивается, один из подмассивов уже полностью пройден, а в другом могут оставаться необработанные элементы:
   - если остались элементы в первом подмассиве (`it1 < arr1_end`) — они по очереди дописываются в буфер;
   - если остались элементы во втором подмассиве (`it2 < arr2_end`) — они аналогично дописываются в буфер.
:::

После того как весь буфер `buffer` заполнен объединёнными в правильном порядке элементами обоих подмассивов, его нужно скопировать обратно в исходный массив — туда, откуда были взяты `arr1` и `arr2`:

```cpp
copy(buffer, buffer_end, arr1)
```

То есть буфер `buffer` копируется на место исходного диапазона `[arr1, arr2_end)`, и на этом процедура слияния (`merge`) заканчивается — данный диапазон массива становится отсортированным.

:::example
Сама сортировка слиянием (mergesort) строится поверх этой процедуры `merge` рекурсивно:

1. Если в переданном диапазоне массива один элемент (или ноль) — он уже отсортирован, рекурсия останавливается.
2. Иначе диапазон делится пополам на две половины.
3. Каждая половина сортируется рекурсивным вызовом mergesort.
4. Две уже отсортированные половины сливаются в одну с помощью описанной выше процедуры `merge`.

```cpp
mergesort(arr, arr_end):
    if arr_end - arr <= 1:
        return
    mid = arr + (arr_end - arr) / 2
    mergesort(arr, mid)
    mergesort(mid, arr_end)
    merge(arr, mid, mid, arr_end)
```
:::
