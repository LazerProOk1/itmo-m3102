# Разбор подсчёта вхождений слова "hello" в файле при потоковом чтении

## Постановка задачи

Дан файл произвольного размера. Его нужно прочитать не целиком за один раз, а небольшими порциями (буферами) фиксированного размера, и при этом посчитать, сколько раз в файле встречается подстрока `"hello"`. Сложность в том, что искомое слово может оказаться разорванным на границе двух соседних порций — например, `"hel"` попадёт в конец одного буфера, а `"lo"` — в начало следующего. Наивная проверка каждого буфера "с нуля" такие случаи пропустит.

:::warning
Если искать `"hello"` в каждом прочитанном куске независимо, не запоминая состояние между вызовами, вхождения, разорванные границей буфера, будут потеряны. Это ключевая проблема, которую решает весь код ниже.
:::

## Буфер и константа размера чтения

```cpp
static const std::size_t BUF_SIZE = 8;
```

:::meaning
`BUF_SIZE` — размер порции данных (в байтах), которая считывается из файла за одно обращение к диску. Здесь выбрано значение 8 — специально маленькое, чтобы наглядно продемонстрировать проблему разрыва слова на границе чтений (слово `"hello"` длиной 5 байт легко не поместится целиком в 8-байтный кусок вместе с соседними символами).
:::

## Автомат состояний для поиска подстроки

Чтобы искать `"hello"` без потери совпадений на границах буферов, используется **конечный автомат** (state machine): вместо того чтобы каждый раз сравнивать сразу пять символов, программа посимвольно продвигается по искомому слову и запоминает, докуда дошло совпадение.

:::meaning
**`match_id`** — переменная состояния автомата. Она хранит, сколько подряд идущих символов искомого слова `"hello"` уже совпало с последними прочитанными символами файла. Например, `match_id = 3` означает: последние три обработанных символа были `"h"`, `"e"`, `"l"`, и автомат ожидает следующим символом `"l"` (четвёртую букву слова).
:::

Логика перехода автомата на каждом символе:

```diagram
title: Переход автомата на один символ
A: round "Очередной символ str[i]" @ 80,40
B: diamond "str[i] == hello[match_id]?" @ 70,180
C: box "match_id++" @ 90,320
D: diamond "match_id == длина hello?" @ 300,310
E: box "match++, match_id = 0" @ 480,320
F: diamond "str[i] == hello[0]?" @ 230,230
G: box "match_id = 1" @ 380,130
H: box "match_id = 0" @ 480,240
A -> B
B -> C : Да
C -> D
D -> E : Да
D -> A : Нет
B -> F : Нет
F -> G : Да
F -> H : Нет
G -> A
H -> A
E -> A
```

:::example
Разберём пошагово, как автомат обработает строку `"helhello"` (представим, что она пришла одним куском):

1. `match_id = 0`. Символ `h` совпадает с `hello[0]`, значит `match_id → 1`.
2. Символ `e` совпадает с `hello[1]`, `match_id → 2`.
3. Символ `l` совпадает с `hello[2]`, `match_id → 3`.
4. Следующий символ — снова `h`, а автомат ожидал `hello[3] = 'l'`. Совпадения нет, переходим в блок `else`: так как этот символ сам равен `hello[0]`, устанавливаем `match_id = 1` (то есть считаем, что новое совпадение только началось).
5. `e` совпадает с `hello[1]`, `match_id → 2`.
6. `l` совпадает с `hello[2]`, `match_id → 3`.
7. `l` совпадает с `hello[3]`, `match_id → 4`.
8. `o` совпадает с `hello[4]`, `match_id → 5`. Поскольку `5` равно длине слова `hello`, засчитывается совпадение: `match++`, `match_id` обнуляется.

Итог: одно найденное вхождение `"hello"`, а первые три буквы `"hel"` не привели к ложному срабатыванию — ровно за счёт того, что при неудаче автомат заново проверяет, не является ли текущий символ началом нового слова.
:::

:::note
Ветка `else` неспроста проверяет `str[i] == hello[0]`, а не просто обнуляет `match_id` в ноль. Если бы там стояло `match_id = 0` безусловно, то при входной строке вроде `"hhello"` первая `h` "потерялась" бы, и слово `hello`, начинающееся сразу со второй буквы, могло бы быть найдено с опозданием или вовсе пропущено при неудачном стечении границ буфера. Проверка `str[i] == hello[0]` — это защита от подобных ложноотрицательных случаев, когда очередной символ одновременно завершает несовпадение и начинает новое потенциальное совпадение.
:::

## Функция `countHello` — состояние через указатель

```cpp
int countHello(const char* str, std::size_t sz, int* match_idp = nullptr) {
    static const char* hello = "hello";
    static const std::size_t hello_sz = strlen(hello);

    int match_id = match_idp ? *match_idp : 0;
    int match = 0;

    for (int i = 0; i<sz; ++i) {
        if (str[i] == hello[match_id]){
            match_id++;
            if (match_id == hello_sz){
                match++;
                match_id=0;
            }
        }
        else {
            match_id = (str[i] == hello[0]) ? 1 : 0;
        }
    }

    if (nullptr!=match_idp){
        *match_idp = match_id;
    }

    return match;
}
```

Разберём компоненты по порядку:

- **Параметры**: `str` — указатель на начало буфера, `sz` — сколько байт в этом буфере реально нужно обработать, `match_idp` — необязательный указатель на переменную состояния автомата из предыдущего вызова.
- **`static const char* hello = "hello";`** и **`hello_sz`** — искомое слово и его длина вычисляются один раз (ключевое слово `static` внутри функции означает, что инициализация происходит при первом вызове, а при последующих вызовах значение переиспользуется, а не пересчитывается заново).

:::meaning
Модификатор `static` у локальной переменной внутри функции означает, что переменная создаётся один раз за всё время работы программы (а не при каждом вызове функции) и сохраняет своё значение между вызовами. Здесь это используется просто как оптимизация — незачем каждый раз заново вызывать `strlen`.
:::

- **Восстановление состояния**: `int match_id = match_idp ? *match_idp : 0;` — если указатель на состояние передан (не `nullptr`), автомат продолжает работу с того значения, на котором остановился в прошлый раз; если указатель не передан — начинает с нуля, как для нового независимого поиска.
- **Основной цикл** — та самая логика автомата, разобранная в примере выше.
- **Сохранение состояния обратно**: `if (nullptr!=match_idp) { *match_idp = match_id; }` — после обработки текущего куска строки текущее состояние автомата записывается обратно по адресу `match_idp`, чтобы следующий вызов функции (на следующем куске файла) мог его подхватить.

:::remember
Именно передача состояния `match_id` между вызовами через указатель (или, как ниже, через структуру) — это и есть механизм, который позволяет находить `"hello"`, даже если слово разорвано границей между двумя прочитанными буферами.
:::

## Структура `HelloCountContext` и функция `countHelloStruct`

```cpp
struct HelloCountContext {
    const char* str;
    std::size_t sz;
    int match_id = 0;
};
```

:::meaning
`HelloCountContext` — структура, объединяющая в одном объекте всё, что нужно функции подсчёта: указатель на текущий буфер (`str`), его длину (`sz`) и состояние автомата (`match_id`). Поле `match_id` инициализировано значением по умолчанию `0` прямо в объявлении структуры — это означает, что при создании нового объекта `HelloCountContext ctx;` без явной инициализации поле `match_id` сразу будет равно нулю.
:::

```cpp
int countHelloStruct(HelloCountContext* ctx) {
    if (nullptr == ctx) {
        return -1;
    }
    static const char* hello = "hello";
    static const std::size_t hello_sz = strlen(hello);

    int match_id = ctx->match_id;
    int match = 0;

    for (std::size_t i = 0; i < ctx->sz; ++i) {
        if (ctx->str[i] == hello[match_id]) {
            match_id++;
            if (match_id == hello_sz) {
                match++;
                match_id = 0;
            }
        } else {
            match_id = (ctx->str[i] == hello[0]) ? 1 : 0;
        }
    }

    ctx->match_id = match_id;

    return match;
}
```

Это по сути та же самая функция `countHello`, но переработанная так, чтобы принимать не три отдельных параметра, а один указатель на структуру:

- Проверка `if (nullptr == ctx) { return -1; }` — защита от разыменования нулевого указателя: если функции передали `nullptr` вместо реального контекста, она не пытается обратиться к полям несуществующего объекта, а сразу возвращает код ошибки `-1`.
- Локальная переменная `match_id` копируется из `ctx->match_id` в начале и записывается обратно в `ctx->match_id` в конце — тот же принцип "прочитать состояние → обработать → сохранить состояние", что и в `countHello`, только через поля структуры, а не через указатель на отдельную переменную.
- Цикл использует `std::size_t i` вместо `int i` — то есть тип переменной цикла здесь соответствует типу `ctx->sz`, чем эта версия отличается от `countHello` (где `i` объявлена как `int`, а сравнивается с `sz` типа `std::size_t`).

:::warning
В функции `countHello` цикл `for (int i = 0; i<sz; ++i)` сравнивает знаковую переменную `int i` с беззнаковой `std::size_t sz`. Компилятор в таком месте обычно предупреждает о сравнении знакового и беззнакового типов. На практике, пока `sz` не превышает диапазон `int`, ошибок это не вызывает, но это пример небрежности, которой стоит избегать: в `countHelloStruct` эта проблема уже устранена — там `i` объявлена как `std::size_t`.
:::

:::note
Зачем в программе присутствуют сразу две почти одинаковые функции — `countHello` (со свободными параметрами и необязательным указателем) и `countHelloStruct` (принимающая структуру)? Это иллюстрация двух разных способов передавать и хранить состояние между вызовами: через отдельный указатель на переменную и через структуру, объединяющую все связанные данные. Второй подход обычно предпочтительнее, когда параметров, которые нужно передавать вместе, становится больше двух-трёх — код читается яснее, и сложнее перепутать порядок аргументов.
:::

## Функция `main`: чтение файла порциями

```cpp
int main(int argc, char** argv) {
    if (argc<2) {
        std::cout << "Argument count error\n";
        return 2;
    }
    FILE* f = fopen(argv[1], "r");

    if (nullptr==f) { 
        std::cout << "File read error\n";
        return 1;
    }
    char buf[BUF_SIZE]{};
    int helloes = 0;
    HelloCountContext ctx;

    std::size_t cnt;
    while ((cnt = fread(buf, sizeof(char), BUF_SIZE, f)) > 0) {
        buf[cnt < BUF_SIZE ? cnt : BUF_SIZE - 1] = '\0';
        std::cout << buf << std::endl;

        ctx.str = buf;
        ctx.sz = cnt;
        helloes += countHelloStruct(&ctx);
    }

    std::cout << helloes << std::endl;
    fclose(f);
    return 0;
}
```

Разберём построчно:

- **`if (argc<2)`** — проверка, что программе передан хотя бы один аргумент командной строки (имя файла). `argc` — количество аргументов, включая имя самой программы, поэтому `argc < 2` означает "имя файла не передано". В этом случае программа выводит сообщение об ошибке и завершается с кодом `2`.
- **`fopen(argv[1], "r")`** — открытие файла, путь к которому взят из первого аргумента командной строки, в режиме чтения текста (`"r"`). Если открыть файл не удалось (например, файла не существует), `fopen` возвращает `nullptr`, что и проверяется следующей строкой; в этом случае программа завершается с кодом `1`.
- **`char buf[BUF_SIZE]{};`** — буфер фиксированного размера `BUF_SIZE` (8 байт), инициализированный нулями (`{}` — списочная инициализация, обнуляющая весь массив).
- **`HelloCountContext ctx;`** — создаётся контекст поиска; благодаря инициализатору поля по умолчанию в структуре, `ctx.match_id` сразу равен `0` — то есть перед началом чтения файла автомат находится в начальном состоянии.
- **Цикл `while ((cnt = fread(...)) > 0)`** — на каждой итерации из файла считывается очередная порция до `BUF_SIZE` байт, а количество реально прочитанных байт сохраняется в `cnt`. Цикл продолжается, пока `fread` возвращает положительное число (то есть пока есть что читать); когда файл заканчивается, `fread` возвращает `0`, и цикл завершается.
- **`buf[cnt < BUF_SIZE ? cnt : BUF_SIZE - 1] = '\0';`** — после каждого чтения в буфер дописывается завершающий нулевой символ, чтобы `buf` можно было безопасно вывести как обычную C-строку через `std::cout`. Тернарный оператор выбирает позицию для `'\0'`: если прочитано меньше, чем `BUF_SIZE` байт (последний, неполный кусок файла), нулевой символ ставится сразу после последнего прочитанного байта (`buf[cnt]`); если прочитано ровно `BUF_SIZE` байт (буфер заполнен полностью), нулевой символ записывается в последнюю ячейку массива — `buf[BUF_SIZE - 1]`.

:::warning
Обратите внимание: если `fread` вернула ровно `BUF_SIZE` (буфер заполнен целиком), строка `buf[BUF_SIZE - 1] = '\0';` **затирает** последний реально прочитанный из файла байт нулевым символом. Это означает, что при выводе (`std::cout << buf`) этот момент нужно держать в уме: сам подсчёт вхождений `"hello"` использует `ctx.sz = cnt` (то есть настоящее количество прочитанных байт, без урезания), поэтому на подсчёт эта перезапись не влияет — обрезается только то, что выводится на экран через `std::cout`. Но это иллюстрирует общий принцип: если данные могут содержать любые байты (в том числе нулевой), нельзя полагаться на них как на C-строку без явного контроля границ.
:::

- **`ctx.str = buf; ctx.sz = cnt;`** — перед вызовом функции подсчёта контекст обновляется: в него записывается указатель на текущий буфер и точное число прочитанных байт (не важно, было ли туда потом записано `'\0'` для вывода).
- **`helloes += countHelloStruct(&ctx);`** — вызывается подсчёт вхождений на текущем куске данных; поскольку `ctx.match_id` не сбрасывается между итерациями цикла (это одна и та же структура `ctx`, объявленная один раз до цикла), состояние автомата корректно переносится с одного чтения файла на следующее — именно это и решает исходную проблему разрыва слова на границе буферов.
- **После цикла** — общее число найденных вхождений `helloes` выводится на экран, файл закрывается функцией `fclose`, и программа завершается с кодом `0` (успех).

:::remember
Ключевая идея всей программы: файл читается порциями фиксированного размера, но состояние автомата поиска (`match_id`) хранится **вне** цикла чтения — в объекте `ctx`, который переиспользуется на каждой итерации. Именно поэтому слово `"hello"`, разорванное границей между двумя чтениями файла, всё равно будет найдено корректно.
:::
