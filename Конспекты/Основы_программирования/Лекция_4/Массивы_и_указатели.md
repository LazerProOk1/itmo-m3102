## 3. Массивы и адресная арифметика

:::meaning
**Массив** — последовательность элементов **одного типа**, расположенных в памяти **подряд**, друг за другом, без промежутков.
:::

- Массив — последовательность элементов **одного типа**.
- Элементы расположены в памяти **подряд**.
- Размер встроенного массива задаётся при создании и **не меняется**.
- Индексация начинается **с нуля**: для массива из `N` элементов допустимы индексы от `0` до `N - 1`.

:::remember
Для массива из `N` элементов допустимые индексы `i` удовлетворяют условию:

$$
0 \le i \le N - 1
$$

Индекс, равный `N` или больше, выходит за границы массива.
:::

Рассмотрим массив из пяти `int` со значениями от 1 до 5:

```array
[1, 2, 3, 4, 5]
```

Элементы занимают в памяти соседние ячейки: индексы идут от `0` до `4`. Если размер `int` равен 4 байтам (`sizeof(int) == 4`), то адреса соседних элементов отличаются на 4 байта, а весь массив занимает:

$$
5 \times 4 = 20 \text{ байт}
$$

:::formula
Размер массива в байтах равен произведению числа элементов на размер одного элемента:

$$
\text{размер массива} = N \times \text{sizeof(T)}
$$
:::

### Объявление массивов

**array-declarations.cpp**

```cpp
#include <iostream>

int main() {
    int uninitialized[10];  // Значения элементов не определены.
    int inferred[] = {1, 2, 3, 4, 5};
    int fixed[3] = {1, 2, 3};
    int matrix[2][3] = {
        {1, 2, 3},
        {4, 5, 6},
    };

    std::cout << sizeof(uninitialized) << '\n';  // Не читаем элементы.
    std::cout << inferred[0] << ' ' << fixed[2] << '\n';
    std::cout << matrix[1][2] << '\n';
}
```

:::example
Разберём, что делает каждая строка `main`:

1. `int uninitialized[10];` — создаёт массив из 10 `int`, но **не инициализирует** его. Значения ячеек неопределены, поэтому программа их не читает — только берёт размер.
2. `int inferred[] = {1, 2, 3, 4, 5};` — размер массива (5) выводится компилятором из количества элементов в списке инициализации.
3. `int fixed[3] = {1, 2, 3};` — размер указан явно и совпадает с числом элементов.
4. `int matrix[2][3] = {...};` — двумерный массив: 2 строки по 3 элемента. Инициализация построчная, вложенными списками в фигурных скобках.
5. `sizeof(uninitialized)` возвращает размер всего массива в байтах — `10 * sizeof(int)`, то есть 40 при `sizeof(int) == 4`.
6. `inferred[0]` — первый элемент (`1`), `fixed[2]` — последний элемент массива `fixed` (`3`).
7. `matrix[1][2]` — элемент второй строки (индекс `1`), третьего столбца (индекс `2`) — значение `6`.
:::

:::note
Индексация двумерного массива, как и одномерного, начинается с нуля по каждому измерению.
:::

### Преобразование массива в указатель

Во многих выражениях массив `T[N]` неявно преобразуется в указатель `T*` на свой первый элемент — `&values[0]`. Это часто называют **array-to-pointer decay**.

:::meaning
**Array-to-pointer decay** — неявное преобразование массива `T[N]` в указатель `T*` на его первый элемент. Происходит:

- при инициализации или присваивании указателя;
- при передаче в функцию с параметром-указателем;
- в адресной арифметике, например `values + 1`.
:::

**array-to-pointer.cpp**

```cpp
#include <iostream>

void PrintFirst(const int* pointer) {
    std::cout << *pointer << '\n';
}

int main() {
    int values[] = {10, 20, 30};
    int* first = values;  // Инициализация указателя: values -> &values[0].
    PrintFirst(values);  // Аргумент функции: values -> &values[0].
    std::cout << *(values + 1) << '\n';  // В арифметике тоже нужен указатель.
    std::cout << values[0] << ' ' << *values << ' ' << *first << '\n';
}
```

:::example
Пошагово:

1. `int* first = values;` — массив `values` превращается в указатель на первый элемент, `first` получает адрес `&values[0]`.
2. `PrintFirst(values);` — при передаче в функцию с параметром `const int* pointer` массив снова превращается в указатель; функция печатает `*pointer`, то есть `10`.
3. `*(values + 1)` — `values` decay-ится в указатель, к нему прибавляется 1 элемент (не байт!), получается адрес `&values[1]`; разыменование даёт `20`.
4. `values[0]`, `*values`, `*first` — три разных способа получить один и тот же первый элемент: `10 10 10`.
:::

:::warning
Преобразование массива в указатель **не копирует элементы** и **не передаёт размер массива**. Указатель хранит только адрес первого элемента — информация о том, сколько всего элементов в массиве, теряется.
:::

Для константного массива результат имеет тип `const T*`.

Правило преобразования описано в стандарте C++: [array-to-pointer conversion](https://eel.is/c++draft/conv.array).

### Когда массив остаётся массивом

Преобразования в указатель **не происходит** в следующих случаях:

- в выражении `sizeof(values)`;
- при взятии адреса всего массива `&values`;
- в `decltype(values)`;
- при связывании массива со **ссылкой на массив**.

**array-without-decay.cpp**

```cpp
#include <iostream>

int main() {
    int values[] = {10, 20, 30};
    int (&reference)[3] = values;  // Ссылка на весь массив.
    int (*whole)[3] = &values;    // Указатель на весь массив.
    decltype(values) copy = {40, 50, 60};  // Тип copy — int[3].

    std::cout << sizeof(values) / sizeof(values[0]) << '\n';  // 3
    std::cout << reference[1] << ' ' << (*whole)[1] << '\n';  // 20 20
    std::cout << copy[0] << '\n';  // 40
}
```

:::example
1. `int (&reference)[3] = values;` — `reference` ссылается на **весь** массив `values` целиком (тип «ссылка на массив из 3 `int`»), а не на отдельный элемент.
2. `int (*whole)[3] = &values;` — `&values` здесь не decay-ится, а даёт указатель на весь массив; тип `whole` — «указатель на массив из 3 `int`».
3. `decltype(values) copy = {40, 50, 60};` — `decltype` сохраняет объявленный тип `values`, то есть `int[3]`, и `copy` — новый независимый массив с этим типом.
4. `sizeof(values) / sizeof(values[0])` — стандартный приём для подсчёта количества элементов массива: размер всего массива делится на размер одного элемента, получаем `3`.
5. `reference[1]` и `(*whole)[1]` — оба обращаются ко второму элементу исходного массива `values`, то есть к `20`. Обратите внимание, что `whole` — указатель на массив, поэтому сначала его нужно разыменовать (`*whole`), и только потом индексировать.
6. `copy[0]` — первый элемент независимой копии массива, `40`.
:::

:::warning
`&values` имеет тип **указателя на весь массив** (`int(*)[3]`), а не указателя на первый `int` (`int*`). Это разные типы, хотя численно адрес один и тот же.
:::

Массив хранит все элементы, указатель — только адрес.

`sizeof` возвращает размер всего массива: [стандарт C++, sizeof](https://eel.is/c++draft/expr.sizeof). `decltype(values)` сохраняет объявленный тип: [стандарт C++, decltype](https://eel.is/c++draft/dcl.type.decltype).

### `sizeof` массива и параметра функции

**array-parameter-size.cpp**

```cpp
#include <iostream>

void PrintSize(int* array) {
    std::cout << sizeof(array) << '\n';
}

int main() {
    int values[10]{};
    std::cout << sizeof(values) << '\n';
    PrintSize(values);
}
```

- `PrintSize(values)` передаёт адрес первого элемента. Параметр `array` — указатель.
- В параметрах функции `int array[]` означает `int* array`.
- Число элементов из указателя не получить: его передают отдельно.

```diagram
A: box "values в main: int[10], 40 байт"
B: box "array в PrintSize: int*, 8 байт"
A -> B : передача в функцию (decay)
```

На схеме предполагается `sizeof(int) == 4` и `sizeof(int*) == 8`.

:::warning
Это одна из самых частых ловушек новичков: `sizeof` массива внутри функции, куда он был передан как параметр, вернёт размер **указателя** (например, 8 байт на 64-битной системе), а не размер всего массива. Причина в том, что параметр `int array[]` на самом деле имеет тип `int*` — информация об исходном размере массива теряется при decay.
:::

:::example
Программа сначала выводит размер всего массива `values` в `main` — `40` (10 элементов по 4 байта). Затем вызывает `PrintSize`, которая выводит размер своего параметра-указателя `array` — `8` (размер указателя на 64-битной системе), а не размер исходного массива.
:::

:::note
Параметр можно записать и как `int array[]` — его тип всё равно будет `int*`. В примере использована явная запись указателя, чтобы `sizeof(array)` не вызывал предупреждение компилятора (например, Clang) о применении `sizeof` к параметру, записанному в форме массива.
:::

### Арифметика указателей

Для указателя на элемент массива прибавление единицы даёт указатель на **следующий** элемент этого же массива.

:::remember
Смещение в адресной арифметике измеряется **в элементах** типа указателя, а не в байтах. Если `pointer` имеет тип `T*`, то `pointer + 1` указывает на адрес, больший на `sizeof(T)` байт, но логически — на «следующий элемент».
:::

**pointer-arithmetic.cpp**

```cpp
#include <iostream>

int main() {
    int values[] = {10, 20, 30};
    int* pointer = values;

    int first = *pointer;         // 10
    int second = *(pointer + 1);  // 20
    int third = pointer[2];       // 30
    std::cout << first << ' ' << second << ' ' << third << '\n';
}
```

### Индексы и смещения

```array
[10, 20, 30] highlight: 0,1,2
```

Указатели `pointer`, `pointer + 1` и `pointer + 2` указывают соответственно на `values[0]`, `values[1]` и `values[2]`; шаг между соседними адресами равен `sizeof(int)` байт.

:::remember
Для допустимого индекса `i` следующие четыре выражения эквивалентны и обращаются к одному и тому же элементу:

- `values[i]`
- `*(values + i)`
- `pointer[i]`
- `*(pointer + i)`
:::

### Границы арифметики указателей

**pointer-bounds.cpp**

```cpp
#include <iostream>

int main() {
    int values[] = {10, 20, 30};
    int* begin = values;
    int* end = values + 3;  // Позиция после последнего элемента.

    for (int* current = begin; current != end; ++current) {
        std::cout << *current << '\n';
    }
}
```

:::meaning
Элементы массива образуют полуоткрытый диапазон:

$$
[\,begin, end)
$$

где `begin` указывает на первый элемент, а `end` — на позицию **сразу после** последнего элемента. Сам `end` в диапазон не входит.
:::

:::example
1. `begin = values` — указывает на `values[0]`.
2. `end = values + 3` — указывает не на существующий элемент, а на «воображаемую» позицию сразу за последним элементом массива из 3 элементов.
3. Цикл `for` идёт от `begin` до `end`, не включая `end`, и на каждом шаге печатает `*current` — так последовательно выводятся `10`, `20`, `30`.
4. Когда `current` становится равен `end`, цикл останавливается — разыменования `end` не происходит.
:::

:::warning
`end` можно **получать** и **сравнивать** с другим указателем — это допустимо и безопасно. Но **разыменовывать** `end` (`*end`) или продвигаться дальше него (`end + 1`) — **неопределённое поведение**. Арифметика указателей определена только внутри одного массива и для позиции сразу после его последнего элемента; выход за эту границу недопустим, даже если результат не разыменовывается.
:::

Подробнее: [стандарт C++, additive operators](https://eel.is/c++draft/expr.add).

## 4. C-строки

:::meaning
**C-строка** — нуль-терминированная последовательность символов `char`, то есть массив символов, который завершается специальным нулевым символом `'\0'`.
:::

- C-строка — нуль-терминированная последовательность символов `char`.
- Завершается нулевым символом **`'\0'`**.
- `'\0'` обозначает конец строки и занимает отдельный элемент массива.
- В длину строки завершающий символ **не входит**.

Например, строка `"Hello world"` занимает 11 символов, включая пробел. Завершающий нулевой символ находится в двенадцатой ячейке, с индексом `11`:

```array
title: "Hello world" как C-строка
["H","e","l","l","o"," ","w","o","r","l","d","\0"] highlight: 11
```

:::remember
**Длина строки** (число «настоящих» символов) и **размер занимаемого ею массива** — разные величины: размер массива на единицу больше длины строки, потому что учитывает завершающий `'\0'`.
:::

### Строковый литерал и изменяемый массив

Строковый литерал в C++ — массив константных символов. Указатель на него должен быть `const char*`.

:::meaning
**Строковый литерал** (например, `"Hello world"`) — это массив константных `char`, живущий в памяти всё время работы программы. Изменять его содержимое нельзя.
:::

**c-string-storage.cpp**

```cpp
#include <iostream>

int main() {
    const char* first = "Hello world";
    char second[] = "Hello world";
    const char* third = second;

    second[0] = 'h';  // Меняем отдельный массив, а не литерал.
    std::cout << first << '\n';  // Hello world
    std::cout << third << '\n';  // hello world
}
```

:::example
1. `const char* first = "Hello world";` — `first` указывает прямо на неизменяемый строковый литерал.
2. `char second[] = "Hello world";` — здесь литерал используется только как инициализатор: компилятор создаёт **отдельный, изменяемый** массив `second` и копирует в него символы литерала.
3. `const char* third = second;` — `third` указывает на массив `second`, но через `const char*` нельзя изменять символы (только читать).
4. `second[0] = 'h';` — меняет первый символ именно массива `second`, а не исходный литерал.
5. Поэтому `first` по-прежнему указывает на неизменённый литерал и печатает `Hello world`, а `third` смотрит на изменённый массив `second` и печатает `hello world`.
:::

:::warning
Попытка изменить сам строковый литерал (например, через указатель, объявленный без `const`) — неопределённое поведение. Именно поэтому указатель на литерал должен быть `const char*`.
:::

### Длина строки

Перемещаем указатель до нулевого символа:

**string-length.cpp**

```cpp
#include <cstddef>
#include <iostream>

std::size_t StringLength(const char* string) {
    std::size_t length = 0;
    while (*string != '\0') {
        ++string;
        ++length;
    }
    return length;
}

int main() {
    std::cout << StringLength("Hello") << '\n';  // 5
    std::cout << StringLength("") << '\n';       // 0
}
```

:::example
Функция `StringLength` идёт по строке символ за символом:

1. Пока текущий символ (`*string`) не равен `'\0'`, указатель `string` сдвигается на следующий символ, а счётчик `length` увеличивается на 1.
2. Как только встречается `'\0'`, цикл останавливается, и функция возвращает накопленную длину.
3. Для `"Hello"` цикл выполнится 5 раз (по числу букв), результат — `5`.
4. Для пустой строки `""` первый же символ — это `'\0'`, цикл не выполнится ни разу, результат — `0`.
:::

:::warning
**Предусловие** функции: ей должен быть передан ненулевой указатель на корректную строку с завершающим `'\0'`. Если это условие нарушено (например, передан массив без `'\0'` или `nullptr`), поведение функции не определено.
:::

### Сравнение строк

Строки сравниваются **посимвольно**. Важно не путать это со сравнением через оператор `==`.

:::warning
Оператор `==`, применённый к двум указателям `char*`, сравнивает **адреса**, а не содержимое строк. Чтобы сравнить содержимое, нужно идти по символам вручную или использовать специальную функцию (например, `std::strcmp`).
:::

Вариант с индексами:

**string-compare-indices.cpp**

```cpp
#include <cstddef>
#include <iostream>

int StringCompare(const char* first, const char* second) {
    std::size_t index = 0;
    while (first[index] != '\0' && first[index] == second[index]) {
        ++index;
    }
    return static_cast<unsigned char>(first[index])
         - static_cast<unsigned char>(second[index]);
}

int main() {
    std::cout << StringCompare("cat", "cat") << '\n';  // 0
    std::cout << StringCompare("cat", "car") << '\n';  // > 0
    std::cout << StringCompare("cat", "cats") << '\n'; // < 0
}
```

### Сравнение строк через указатели

Ту же операцию можно выразить через арифметику указателей:

**string-compare-pointers.cpp**

```cpp
#include <iostream>

int StringCompare(const char* first, const char* second) {
    while (*first != '\0' && *first == *second) {
        ++first;
        ++second;
    }
    return static_cast<unsigned char>(*first)
         - static_cast<unsigned char>(*second);
}

int main() {
    std::cout << StringCompare("cat", "cat") << '\n';  // 0
    std::cout << StringCompare("cat", "car") << '\n';  // > 0
    std::cout << StringCompare("cat", "cats") << '\n'; // < 0
}
```

:::example
Обе версии `StringCompare` работают одинаково, только одна использует индексацию (`first[index]`), а другая — прямую арифметику указателей (`*first`, `++first`). Разберём вызовы:

1. `StringCompare("cat", "cat")` — все символы совпадают вплоть до `'\0'`; цикл доходит до конца обеих строк, разность двух нулевых символов равна `0`.
2. `StringCompare("cat", "car")` — символы совпадают до индекса 2 (`'c'`, `'a'`), а на третьем символ `'t'` (код больше) сравнивается с `'r'` (код меньше) — результат положительный.
3. `StringCompare("cat", "cats")` — первая строка короче: на индексе 3 у неё оказывается `'\0'`, а у второй строки — `'s'`. Так как код `'\0'` меньше кода любой буквы, результат отрицательный.
:::

:::remember
Итог сравнения строк:

- **0** — строки равны;
- **< 0** — первая строка идёт раньше второй (в лексикографическом порядке);
- **> 0** — первая строка идёт позже второй.

Символы при этом сравниваются как `unsigned char`, чтобы избежать неопределённого поведения при работе со знаковым `char`.
:::

### Почему C-строки опасны

**c-string-boundaries.cpp**

```cpp
#include <cstring>
#include <iostream>

int main() {
    const char raw[3] = {'C', '+', '+'};  // Нет завершающего '\0'.
    const char text[4] = "C++";          // Есть место для '\0'.

    std::cout << sizeof(raw) << '\n';        // 3
    std::cout << sizeof(text) << '\n';       // 4
    std::cout << std::strlen(text) << '\n';  // 3
    // std::cout << std::strlen(raw);  // Неопределённое поведение.
}
```

:::example
1. `raw` — массив из 3 символов `'C'`, `'+'`, `'+'`, без места под `'\0'`. Формально это уже **не C-строка**.
2. `text` — массив из 4 символов: три буквы плюс автоматически добавленный `'\0'` в конце (компилятор сам выделяет для него ячейку при инициализации строковым литералом).
3. `sizeof(raw)` и `sizeof(text)` возвращают размеры массивов целиком — `3` и `4` соответственно.
4. `std::strlen(text)` ищет `'\0'` и считает символы до него — получает `3` (сам терминатор в длину не входит).
5. Вызов `std::strlen(raw)` закомментирован намеренно: `raw` не является корректной C-строкой, и `strlen` будет читать память **за границей массива** в поисках несуществующего `'\0'` — это неопределённое поведение.
:::

:::warning
Без `'\0'` массив символов **не является C-строкой**, даже если выглядит как текст. Функция `strlen` (и любая другая функция, работающая с C-строками) ищет терминатор и не может сама проверить, есть ли он вообще — она просто читает память, пока не найдёт байт, равный нулю, рискуя выйти за границы выделенной памяти.
:::

:::note
При записи в буфер нужно заранее учитывать его вместимость: для строки `"C++"` требуется **4 ячейки `char`**, включая завершающий `'\0'`. Функция `strlen` не получает вместимость буфера в качестве аргумента и не может проверить её сама — контролировать границы обязан программист.
:::

### Аргументы командной строки

В традиционной форме `main` получает количество аргументов и массив указателей на строки.

:::meaning
- `argc` — количество аргументов командной строки, с которыми запущена программа (включая имя самой программы).
- `argv` — массив указателей на C-строки; `argv[index]` указывает на C-строку с соответствующим аргументом.
:::

**command-line-arguments.cpp**

```cpp
#include <iostream>

int main(int argc, char* argv[]) {
    for (int index = 0; index < argc; ++index) {
        std::cout << argv[index] << '\n';
    }

    return 0;
}
```

Цикл проходит по всем аргументам от `0` до `argc - 1` и печатает каждую C-строку из `argv`.

## 5. Универсальный указатель `void*`

:::meaning
**`void*`** — указатель, который может хранить адрес объекта **любого** типа, но «забывает» этот тип. Чтобы обратиться к объекту через `void*`, тип нужно явно восстановить.
:::

**void-pointer.cpp**

```cpp
#include <iostream>

int main() {
    int value = 239;
    int* typed_pointer = &value;
    void* untyped_pointer = typed_pointer;
    int* restored_pointer = static_cast<int*>(untyped_pointer);

    std::cout << *restored_pointer << '\n';  // 239
}
```

:::example
1. `typed_pointer` хранит адрес `value` с типом `int*`.
2. `untyped_pointer` получает тот же адрес, но с типом `void*` — компилятор теперь «не знает», объект какого типа лежит по этому адресу.
3. Чтобы прочитать значение, тип нужно восстановить явно: `static_cast<int*>(untyped_pointer)` возвращает указателю тип `int*`.
4. Разыменование `restored_pointer` даёт исходное значение — `239`.
:::

:::warning
Разыменовать `void*` напрямую (`*untyped_pointer`) **нельзя** — у компилятора нет информации о размере и устройстве объекта, на который указывает `void*`. Чтение объекта через указатель **несовместимого** типа (например, восстановление не тем типом, каким объект был на самом деле) может привести к неопределённому поведению.
:::

### `void*`: адрес без типа

```diagram
A: box "untyped_pointer (void*)"
B: db "Объект в памяти (тип неизвестен)"
A -> B : хранит адрес
```

Указатель `void*` хранит только адрес — сам он не несёт информации о том, что за данные лежат по этому адресу.

### Просмотр объекта как последовательности байтов

**print-bytes.cpp**

```cpp
#include <cstddef>
#include <format>
#include <iostream>

void PrintBytes(const void* object, std::size_t size) {
    const auto* bytes = (const unsigned char*)object;
    for (std::size_t index = 0; index < size; ++index) {
        std::cout << std::format("{:08b} ", bytes[index]);
    }
    std::cout << '\n';
}

int main() {
    int value = 2 << 10;
    PrintBytes(&value, sizeof(value));
    value = 239;
    PrintBytes(&value, sizeof(value));
}
```

:::example
1. `PrintBytes` принимает адрес произвольного объекта (`const void* object`) и его размер в байтах (`size`).
2. Внутри функции указатель приводится к `const unsigned char*` — теперь по нему можно читать память **побайтово**, независимо от исходного типа объекта.
3. Цикл проходит по всем байтам объекта: `bytes[index]` даёт значение очередного байта, которое печатается в двоичном виде (`{:08b}` — формат с 8 битами и ведущими нулями).
4. `PrintBytes(&value, sizeof(value))` вызывается дважды: сначала для `value = 2 << 10`, затем для `value = 239` — каждый раз печатается побайтовое представление текущего значения `int`.
:::

:::meaning
`std::format` — функция форматирования строк, появившаяся в **C++20**.
:::

:::note
Увеличение индекса `bytes[index]` перемещает чтение ровно на **один байт**, потому что тип `bytes` — указатель на `unsigned char`, а `sizeof(unsigned char) == 1`. Квалификатор `const` в сигнатуре `PrintBytes` сохраняется на всех этапах: функция только читает данные и не может их изменить.
:::

Доступ к представлению объекта через `unsigned char` разрешён правилами доступа по типу: [стандарт C++, basic.lval](https://eel.is/c++draft/basic.lval).

### Порядок байтов

Порядок байтов многобайтового числа зависит от платформы.

:::meaning
- **Little-endian** — младший байт числа хранится по младшему адресу.
- **Big-endian** — старший байт числа хранится по младшему адресу (порядок обратный).
:::

Рассмотрим значение `value = 2 << 10` из примера с `PrintBytes` — это `2048`, или `0x00000800` в шестнадцатеричном виде, — и сравним, как его байты располагаются в памяти по возрастанию адреса на разных архитектурах:

```array
title: Little-endian
["0x00", "0x08", "0x00", "0x00"] highlight: 1
```

```array
title: Big-endian
["0x00", "0x00", "0x08", "0x00"] highlight: 2
```

Индексы `0`–`3` здесь соответствуют возрастающим адресам в памяти. Значимый байт `0x08` в little-endian лежит по младшему адресу (индекс `1`, ближе к началу), а в big-endian — по более старшему адресу (индекс `2`), потому что порядок байтов зеркально противоположен.

:::warning
Функция `PrintBytes` из предыдущего примера покажет **разный** порядок байтов на little-endian и big-endian системах для одного и того же значения — это нужно учитывать, если код опирается на конкретное байтовое представление чисел (например, при сериализации данных или сетевом обмене).
:::

## 6. Указатели на функции

Адрес можно получить не только у объекта, но и у функции.

:::meaning
**Указатель на функцию** — переменная, хранящая адрес функции. Тип такого указателя включает тип возвращаемого значения и типы параметров функции, например `int (*)(int)` — указатель на функцию, принимающую `int` и возвращающую `int`.
:::

**function-pointers.cpp**

```cpp
int same(int value) {
    return value;
}

int main() {
    int (*function)(int) = same;
    int (*same_function)(int) = &same;

    return function(2) + same_function(2) == 4 ? 0 : 1;
}
```

:::note
Оператор взятия адреса перед именем функции необязателен: `same` и `&same` дают один и тот же подходящий указатель на функцию — так же, как массив сам «превращается» в указатель на первый элемент.
:::

### Функция как параметр алгоритма

Функция сравнения задаёт, каким элементом заменить текущий результат.

**find-by-order.cpp**

```cpp
#include <cstddef>
#include <iostream>

int* FindByOrder(int* array, std::size_t size, bool (*comes_before)(int, int)) {
    if (size == 0) return nullptr;
    int* result = array;
    for (std::size_t index = 1; index < size; ++index) {
        if (comes_before(*result, array[index])) {
            result = &array[index];
        }
    }
    return result;
}

bool Less(int left, int right) {
    return left < right;
}

int main() {
    int values[] = {3, 1, 4};
    std::cout << *FindByOrder(values, 3, Less) << '\n';  // 4
    std::cout << (FindByOrder(values, 0, Less) == nullptr) << '\n';  // 1
}
```

:::example
1. `FindByOrder` принимает массив, его размер и указатель на функцию сравнения `comes_before`.
2. Если размер `0`, сразу возвращается `nullptr` — сравнивать нечего.
3. Иначе `result` начинается с первого элемента, и для каждого следующего элемента проверяется: должен ли текущий результат «уступить место» новому элементу — то есть верно ли `comes_before(*result, array[index])`.
4. Если да, `result` обновляется на адрес нового элемента.
5. Для `values = {3, 1, 4}` и функции `Less` (левый меньше правого) алгоритм ищет элемент, перед которым «должны стоять» все остальные в смысле `Less`, — то есть **наибольший** элемент. Результат — `4`.
6. Вызов с `size == 0` возвращает `nullptr`; сравнение `(... == nullptr)` даёт `true`, что при выводе в `std::cout` печатается как `1`.
:::

:::meaning
`bool (*comes_before)(int, int)` — параметр-указатель на функцию, которая принимает два `int` и возвращает `bool`. Именно эта функция определяет **порядок**, по которому `FindByOrder` ищет нужный элемент.
:::

### Выбор порядка сравнения

Две функции с подходящей сигнатурой задают разные варианты сравнения.

**comparison-functions.cpp**

```cpp
#include <iostream>

bool Less(int left, int right) {
    return left < right;
}

bool Greater(int left, int right) {
    return left > right;
}

int main() {
    bool (*comes_before)(int, int) = Less;
    std::cout << comes_before(1, 2) << '\n';  // 1
    comes_before = Greater;
    std::cout << comes_before(1, 2) << '\n';  // 0
}
```

:::remember
`Less` заставляет `FindByOrder` заменять результат **бо́льшим** элементом на каждом шаге — в итоге находится **максимум**. `Greater` — наоборот, заменяет результат **меньшим** элементом, и в итоге находится **минимум**.
:::

:::example
1. `comes_before = Less;` — указатель хранит адрес `Less`. Вызов `comes_before(1, 2)` эквивалентен `Less(1, 2)`, то есть `1 < 2` — `true`, печатается `1`.
2. `comes_before = Greater;` — тот же указатель теперь хранит адрес `Greater`. Вызов `comes_before(1, 2)` эквивалентен `Greater(1, 2)`, то есть `1 > 2` — `false`, печатается `0`.
3. Одна и та же переменная-указатель в разное время «переключает» поведение, в зависимости от того, на какую функцию она указывает.
:::

### Поиск максимума и минимума

**find-extremes.cpp**

```cpp
#include <cstddef>
#include <iostream>

int* FindByOrder(int* array, std::size_t size, bool (*comes_before)(int, int)) {
    if (size == 0) return nullptr;
    int* result = array;
    for (std::size_t index = 1; index < size; ++index) {
        if (comes_before(*result, array[index])) {
            result = &array[index];
        }
    }
    return result;
}

bool Less(int left, int right) {
    return left < right;
}

bool Greater(int left, int right) {
    return left > right;
}

int main() {
    int values[] = {1, 2, 3, 4, 5, 6, 7, 8};
    std::cout << *FindByOrder(values, 8, Less) << '\n';     // 8
    std::cout << *FindByOrder(values, 8, Greater) << '\n';  // 1
}
```

:::example
Передавая одну и ту же функцию `FindByOrder`, но разные функции сравнения, получаем два разных результата на одном и том же массиве `{1, ..., 8}`:

- с `Less` алгоритм ищет наибольший элемент — результат `8`;
- с `Greater` алгоритм ищет наименьший элемент — результат `1`.

Это иллюстрирует главную идею указателей на функции: **поведение алгоритма можно настраивать**, передавая ему разные функции, без изменения кода самого алгоритма.
:::

:::note
В современном C++ вместо обычного указателя на функцию для той же цели также применяют функциональные объекты, лямбда-выражения и `std::function`.
:::

### Как прочитать объявление `signal`

Функция может принимать указатель на функцию и возвращать указатель на функцию.

**signal-declaration.cpp**

```cpp
namespace example {
    void (*signal(int number, void (*handler)(int)))(int);

    using Handler = void (*)(int);
    Handler signal(int number, Handler handler);  // То же объявление.
}

int main() {}
```

:::meaning
- `number` — параметр типа `int`, номер сигнала.
- `handler` — указатель на функцию, принимающую `int` и возвращающую `void`.
- Результат `signal` имеет тот же тип, что и `handler`: это **указатель на функцию**, принимающую `int` и возвращающую `void`.
- `using Handler = void (*)(int);` даёт этому типу указателя имя `Handler` и заметно упрощает чтение объявления.
:::

:::example
Разберём «сырое» объявление `void (*signal(int number, void (*handler)(int)))(int);` изнутри наружу:

1. `signal(int number, void (*handler)(int))` — это вызов функции `signal` с параметрами `number` (типа `int`) и `handler` (указателем на функцию `void(int)`).
2. Всё выражение обёрнуто в `void (* ... )(int)` — значит, результатом вызова `signal` является **указатель на функцию**, принимающую `int` и возвращающую `void`.
3. Введение псевдонима `using Handler = void (*)(int);` позволяет записать то же самое короче: `Handler signal(int number, Handler handler);` — читается гораздо легче, но означает ровно то же самое.
:::

:::note
Учебный пример показывает две эквивалентные записи одного объявления внутри `namespace example`, без вызова функции и без регистрации обработчиков сигналов. Служебные детали языкового связывания настоящей стандартной функции здесь опущены: `std::signal` объявлена в заголовке `<csignal>`, и использовать её нужно именно через этот заголовок, а не через собственное объявление: [стандарт C++, csignal synopsis](https://eel.is/c++draft/csignal.syn).
:::
