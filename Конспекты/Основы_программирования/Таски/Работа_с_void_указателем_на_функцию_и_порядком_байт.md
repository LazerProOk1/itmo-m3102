# Работа с void*, указателем на функцию и порядком байт: разбор функции ModifyASafe

## Постановка задачи и общая идея

Это дополнительное задание (доп. таск) на защите лабораторной работы по основам программирования. Его дал практик Влад Сергей.

Нужно написать универсальную функцию `ModifyASafe`, которая работает с массивом **любого типа**, не зная заранее, что в нём лежит. Функция получает:

- `arr` — адрес начала массива (тип `void*`, потому что тип элементов неизвестен);
- `arr_sz` — размер **одного элемента** в байтах;
- `num` — количество элементов в массиве;
- `idx` — индекс элемента, с которым нужно работать;
- `nult` — указатель на функцию-«условие», которая решает, что делать с элементом.

Алгоритм: проверить аргументы, вычислить адрес элемента с номером `idx`, передать его в функцию `nult`. Если `nult` вернула `true`, вернуть адрес элемента, иначе вернуть `nullptr`.

В качестве функции `nult` используется `NullifyIfOdd`: она смотрит, нечётно ли число, лежащее по переданному адресу, и если нечётно — обнуляет все его байты.

```cpp
#include <iostream>
#include <cstddef>

const int ARR_SIZE = 5;

bool NullifyIfOdd(void* val, size_t sz) {
    unsigned char* a = (unsigned char*)val;
    bool odd = *a % 2 == 1;
    if (odd) {
        for (size_t i = 0; i < sz; i++) {
            a[i] = 0;
        }
    }
    return odd;
}

void* ModifyASafe(void* arr, size_t arr_sz, int num, int idx, bool (*nult)(void*, size_t)) {
    if (nullptr == arr || nullptr == nult) {
        return nullptr;
    }
    if (0 > num || 0 > idx || idx >= num || 0 == arr_sz) {
        return nullptr;
    }
    unsigned char* p = (unsigned char*)arr;
    p += arr_sz * idx;
    if (nult(p, arr_sz)) {
        return (void*)p;
    }
    return nullptr;
}

int main() {
    unsigned arr[ARR_SIZE] = {1, 2, 3, 4, 5};
    unsigned* a = (unsigned*)(ModifyASafe(arr, sizeof(unsigned), ARR_SIZE, 2, &NullifyIfOdd));
    if (nullptr == a) {
        std::cout << "nullptr";
        return 1;
    }
    std::cout << *a;
    return 0;
}
```

Программа выводит `0`: элемент `arr[2]` равен 3, он нечётный, поэтому обнуляется.

:::meaning
**Безопасная** функция (`Safe`) — такая, которая сначала проверяет все входные данные (нулевые указатели, выход индекса за границы, нулевой размер элемента) и только потом обращается к памяти. При любой некорректности она возвращает `nullptr`, а не падает.
:::

Блок-схема работы `ModifyASafe`:

```diagram

B: diamond "arr или nult равны nullptr?"
```

## Литералы

:::meaning
**Литерал** — значение, записанное прямо в тексте программы. У литерала нет имени: это не переменная, а сама константа, «зашитая» в код.
:::

Основные виды литералов в C++:

| Вид | Примеры | Тип |
|---|---|---|
| Целое десятичное | `5`, `42` | `int` |
| Целое шестнадцатеричное | `0x1F` (это 31) | `int` |
| Целое восьмеричное | `017` (это 15) | `int` |
| Целое двоичное | `0b101` (это 5) | `int` |
| С суффиксом | `5u`, `5L`, `5ul` | `unsigned`, `long`, `unsigned long` |
| Вещественное | `3.14`, `2.5f` | `double`, `float` |
| Символьный | `'a'`, `'\n'` | `char` |
| Строковый | `"nullptr"` | массив `const char` |
| Логический | `true`, `false` | `bool` |
| Нулевой указатель | `nullptr` | `std::nullptr_t` |

Литералы, которые встречаются в разбираемом коде:

- `1, 2, 3, 4, 5` в инициализации массива `arr`;
- `2` — индекс элемента, передаваемый в функцию;
- `0` и `1` — в проверках `0 > num`, `0 == arr_sz`, `a[i] = 0`, `... == 1`, `return 1`, `2` в операции `% 2`;
- `"nullptr"` — строковый литерал, который печатается в `std::cout`;
- `nullptr` — литерал нулевого указателя (ключевое слово), которым проверяются и возвращаются указатели.

:::warning
`"nullptr"` в кавычках и `nullptr` без кавычек — разные вещи. Первое — строка из семи букв (в памяти она занимает 8 байт: ещё один нулевой символ `'\0'` в конце). Второе — значение «указатель никуда не указывает».
:::

:::note
Строковый литерал нельзя изменять: попытка записать что-то в его символы приводит к неопределённому поведению. Целый литерал нельзя «взять по адресу»: запись `&5` не компилируется, так как у числа 5 в тексте программы нет места в памяти, которое можно назвать.
:::

:::note
Литерал `0` в проверках вроде `0 > num` стоит слева от переменной. Такая запись (и `nullptr == arr`) защищает от опечатки: если случайно написать `=` вместо `==`, компилятор выдаст ошибку, так как присваивать литералу нельзя.
:::

## Указатель void* и арифметика указателей

### Что такое void*

:::meaning
**`void*`** — универсальный (нетипизированный) указатель. Он хранит только адрес в памяти и ничего не знает о том, объект какого типа и какого размера там лежит.
:::

Свойства `void*`:

1. В него можно записать адрес объекта **любого** типа. В C++ преобразование `T*` → `void*` выполняется неявно.
2. Обратно, из `void*` в `T*`, неявного преобразования нет — нужно явное приведение: `(char*)val` или `static_cast<char*>(val)`.
3. Его **нельзя разыменовывать**: компилятор не знает, сколько байт читать и как их трактовать.
4. С ним **нельзя выполнять арифметику** (см. ниже).

Именно поэтому в сигнатуре функции появляется отдельный параметр `arr_sz`: сам `void*` размера элемента не несёт, и его приходится передавать вручную (в `main` — как `sizeof(unsigned)`).

:::warning
Если передать неверный `arr_sz` (например, `sizeof(char)` для массива `unsigned`), функция не заметит ошибки: она сдвинет указатель не на тот байт и будет работать с «мусором». Компилятор здесь не поможет, так как вся информация о типе потеряна.
:::

Результат `ModifyASafe` тоже имеет тип `void*`, поэтому в `main` его приводят обратно к `unsigned*`: только вызывающий код знает, что на самом деле находится в массиве.

### Арифметика указателей: что можно, а что нельзя

Для указателя `T* p`, который указывает на элемент массива:

| Операция | Можно? | Смысл |
|---|---|---|
| `p + n`, `p - n` | да | Сдвиг на `n` элементов, то есть на `n * sizeof(T)` байт |
| `p++`, `p--`, `p += n`, `p -= n` | да | То же, с изменением самого `p` |
| `p2 - p1` | да | Количество элементов между адресами (тип `ptrdiff_t`); только для указателей на один и тот же массив |
| `p1 == p2`, `p1 < p2` | да | Сравнение адресов (для `<`, `>` — внутри одного массива) |
| `p1 + p2` | нет | Сумма двух адресов не имеет смысла |
| `p * n`, `p / n` | нет | Умножать и делить адреса бессмысленно |

Итак, складывать указатель с целым числом и вычитать из него целое число можно; вычитать один указатель из другого можно; складывать два указателя — нельзя.

:::formula
При сдвиге на $n$ элементов адрес меняется на $n \cdot \text{sizeof}(T)$ байт:

$$
\text{addr}(p + n) = \text{addr}(p) + n \cdot \text{sizeof}(T)
$$
:::

Например, для `unsigned* p`, где `sizeof(unsigned) = 4`, выражение `p + 3` сдвигает адрес на $3 \cdot 4 = 12$ байт. Выражение `arr[i]` — это то же самое, что `*(arr + i)`.

:::warning
Допустимые адреса для указателя на массив из $N$ элементов — от начала массива до **одной позиции за концом** (`arr + N`). Но разыменовывать `arr + N` нельзя, а любой адрес за пределами этого диапазона даёт неопределённое поведение. Поэтому допустимые индексы — от $0$ до $N - 1$ включительно, и проверка в функции должна отвергать `idx >= num`.
:::

### Почему в ModifyASafe массив приводится к char*

Арифметика определяется через `sizeof(T)`, а у `void` размера нет, поэтому по стандарту C++ `arr + 1` для `void*` не компилируется (некоторые компиляторы разрешают это как расширение и считают размер единицей, но полагаться на это нельзя).

Решение — привести указатель к типу, размер которого точно известен и равен 1 байту (`char` или `unsigned char`). Тогда `p += k` сдвигает адрес ровно на `k` байт. Остаётся вычислить `k`:

$$
k = \text{arr\_sz} \cdot \text{idx}
$$

В коде: `p += arr_sz * idx;`. Для `arr_sz = 4`, `idx = 2` получается сдвиг на 8 байт, то есть `p` указывает точно на `arr[2]` (то же самое, что `(unsigned*)arr + 2`).

:::note
Используется именно `unsigned char*`, а не просто `char*`. Тип `char` на многих платформах знаковый, и байт со значением больше 127 превращается в отрицательное число. Тогда `%2` может дать `-1`, а не `1`, и проверка `== 1` не сработает (например, для числа 255, первый байт которого равен `0xFF`). С `unsigned char` значения байта лежат в диапазоне от 0 до 255, и проверка чётности работает верно.
:::

## Указатель на функцию

:::meaning
**Указатель на функцию** — переменная, которая хранит адрес функции (место в памяти, где начинается её код). Через такой указатель функцию можно вызвать, а также передать в другую функцию как параметр.
:::

В `ModifyASafe` указатель на функцию — это параметр `nult`. Его объявление:

```cpp
bool (*nult)(void*, size_t)
```

Читается так: `nult` — это указатель (`*nult`) на функцию, которая принимает `void*` и `size_t` и возвращает `bool`.

:::warning
Скобки вокруг `*nult` обязательны. Запись `bool *nult(void*, size_t)` без скобок означает совсем другое: объявление **функции** `nult`, возвращающей `bool*`.
:::

Что с таким указателем делают:

1. **Получение адреса функции.** В `main` передаётся `&NullifyIfOdd`. Оператор `&` здесь необязателен: имя функции само преобразуется в указатель на неё, поэтому `NullifyIfOdd` и `&NullifyIfOdd` означают одно и то же.
2. **Проверка на `nullptr`.** Как и любой указатель, указатель на функцию может быть нулевым. Вызов через `nullptr` приведёт к аварийному завершению, поэтому `ModifyASafe` проверяет `nullptr == nult` до вызова.
3. **Вызов.** `nult(p, arr_sz)` или, что то же самое, `(*nult)(p, arr_sz)`. Вызывается та функция, адрес которой лежит в указателе.

Смысл приёма: `ModifyASafe` не знает, что именно делать с элементом. Это решает функция, переданная снаружи. Подставив другую функцию с той же сигнатурой (`bool (void*, size_t)`), можно получить другое поведение без изменения `ModifyASafe`. Поэтому сигнатура условия тоже использует `void*`: условие должно принимать элемент любого типа.

:::note
Сигнатура передаваемой функции должна совпадать с типом указателя полностью: число и типы параметров и тип возвращаемого значения. `NullifyIfOdd` имеет сигнатуру `bool (void*, size_t)`, как и требует параметр `nult`.
:::

## Порядок байт: little-endian и big-endian

Переменная типа `unsigned` занимает в памяти несколько байт (обычно 4). Возникает вопрос: в каком порядке эти байты записаны по возрастанию адресов?

:::meaning
**Little-endian** (от меньшего к большему) — первым, по наименьшему адресу, хранится **младший** байт числа.

**Big-endian** (от большего к меньшему) — первым хранится **старший** байт числа.
:::

Число $3 = \texttt{0x00000003}$ состоит из четырёх байт: старшие три равны `00`, младший равен `03`. Его представление в памяти:

```array
title: Little-endian: число 3 (0x00000003)
caption: Первый по адресу байт — младший
[3, 0, 0, 0] i=0 highlight: 0
```

```array
title: Big-endian: число 3 (0x00000003)
caption: Первый по адресу байт — старший
[0, 0, 0, 3] i=0 highlight: 0
```

Число из четырёх байт $b_3 b_2 b_1 b_0$ (где $b_0$ — младший) вычисляется так:

$$
N = b_0 + b_1 \cdot 256 + b_2 \cdot 256^2 + b_3 \cdot 256^3
$$

### Как порядок байт связан с NullifyIfOdd

Функция `NullifyIfOdd` получает `void*` и читает **только первый байт** по этому адресу: `*a % 2`. Чтобы так проверять чётность, нужно, чтобы первый байт был младшим. Почему младший байт решает вопрос о чётности: все остальные слагаемые в формуле выше кратны 256, то есть чётны, поэтому

$$
N \bmod 2 = b_0 \bmod 2
$$

Отсюда следствия:

- На **little-endian** платформе (к ним относятся компьютеры на процессорах x86 и большинство ARM-систем) первый байт — это $b_0$, и проверка работает верно: для числа 3 читается байт `03`, он нечётен, число нечётно.
- На **big-endian** платформе первый байт — это $b_3$ (для числа 3 он равен 0). Функция посчитает число чётным и вернёт `false`, хотя число нечётно.

:::warning
Код, который читает отдельные байты числа через `char*`, зависит от порядка байт платформы. Для переносимой проверки нужно либо знать порядок байт, либо обращаться к числу его собственным типом (`unsigned`), а не через байты.
:::

Порядок байт можно определить на лету: записать в `unsigned` значение 1 и прочитать его первый байт. Если он равен 1 — платформа little-endian, если 0 — big-endian.

```cpp
unsigned x = 1;
bool little = *(unsigned char*)&x == 1;
```

:::note
Обнуление в `NullifyIfOdd` от порядка байт не зависит: оно записывает нули во все `sz` байт подряд, а нулевое значение выглядит одинаково при любом порядке.
:::

## Построчный разбор функций

### NullifyIfOdd

```cpp
bool NullifyIfOdd(void* val, size_t sz) {
    unsigned char* a = (unsigned char*)val;
    bool odd = *a % 2 == 1;
    if (odd) {
        for (size_t i = 0; i < sz; i++) {
            a[i] = 0;
        }
    }
    return odd;
}
```

1. `val` — адрес элемента (тип неизвестен), `sz` — его размер в байтах.
2. `a` — тот же адрес, но уже как указатель на байты: так его можно разыменовывать и индексировать.
3. `*a % 2 == 1` — первый (младший на little-endian) байт нечётен?
4. Если да, цикл обнуляет все `sz` байт элемента. Для `unsigned` это четыре байта, и число становится равным 0.
5. Функция возвращает `odd`: `true`, если элемент был нечётным (и обнулён).

### ModifyASafe

```cpp
void* ModifyASafe(void* arr, size_t arr_sz, int num, int idx, bool (*nult)(void*, size_t)) {
    if (nullptr == arr || nullptr == nult) {
        return nullptr;
    }
    if (0 > num || 0 > idx || idx >= num || 0 == arr_sz) {
        return nullptr;
    }
    unsigned char* p = (unsigned char*)arr;
    p += arr_sz * idx;
    if (nult(p, arr_sz)) {
        return (void*)p;
    }
    return nullptr;
}
```

1. **Проверка указателей.** Пустой массив или пустая функция — нечего обрабатывать, возвращается `nullptr`.
2. **Проверка чисел.** Отрицательное количество элементов, отрицательный индекс, индекс за границей (`idx >= num`) и нулевой размер элемента недопустимы.
3. **Приведение к байтам.** `p` — указатель на байты, чтобы выполнять арифметику (см. выше).
4. **Сдвиг к нужному элементу.** `p += arr_sz * idx`: пропускаем `idx` элементов по `arr_sz` байт каждый.
5. **Вызов условия.** `nult(p, arr_sz)` — вызов функции по указателю. Если она вернула `true`, возвращается адрес элемента (в виде `void*`), иначе — `nullptr`.

:::example
Пошаговая трассировка программы из раздела «Постановка задачи». В `main` создан массив `arr = {1, 2, 3, 4, 5}`, вызывается `ModifyASafe(arr, 4, 5, 2, &NullifyIfOdd)`.

1. Указатели ненулевые, `num = 5`, `idx = 2`, `arr_sz = 4`: условия проверки не срабатывают, ошибки нет.
2. `p` указывает на начало массива, затем `p += 4 * 2`: сдвиг на 8 байт, `p` указывает на `arr[2]`, то есть на число 3.
3. Вызывается `NullifyIfOdd(p, 4)`. Первый байт (на little-endian) равен 3, остаток от деления на 2 равен 1, значит число нечётно.
4. Все четыре байта обнуляются: `arr[2]` становится 0. Функция возвращает `true`.
5. `ModifyASafe` возвращает `p` как `void*`. В `main` он приводится к `unsigned*` и записывается в `a`.
6. `a` не равен `nullptr`, поэтому выводится `*a`, то есть `0`.

Те же действия над массивом в виде пошагового выполнения:

```array
title: Обнуление нечётного элемента arr[2]
caption: Указатель p показывает на элемент с номером idx
[1, 2, 3, 4, 5]
pointers: p
print: last
code:
let idx = 2;
let p = idx;
if (a[p] % 2 == 1) {
  a[p] = 0;
}
```
:::

:::example
Если вызвать функцию с `idx = 1`, элемент `arr[1]` равен 2 и чётный. `NullifyIfOdd` возвращает `false`, ничего не обнуляя, `ModifyASafe` возвращает `nullptr`, и `main` печатает `nullptr` и завершается с кодом 1.

Если вызвать с `idx = 5` (равным `num`), проверка `idx >= num` срабатывает, и функция возвращает `nullptr`, не обращаясь к памяти за концом массива.
:::
