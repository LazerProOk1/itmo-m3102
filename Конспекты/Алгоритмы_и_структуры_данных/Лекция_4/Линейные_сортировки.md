# Сортировка подсчётом и поразрядная сортировка

## Сортировка подсчётом (Counting sort)

### Идея алгоритма

Сортировка подсчётом — это алгоритм сортировки, который не сравнивает элементы между собой (как это делают, например, быстрая или пирамидальная сортировка), а вместо этого **подсчитывает, сколько раз встречается каждое значение** из заранее известного диапазона.

:::meaning
**Сортировка подсчётом (Counting sort)** — алгоритм сортировки массива $A$, элементы которого — целые числа из известного диапазона (алфавита), основанный на подсчёте количества вхождений каждого значения.
:::

Для работы алгоритма заводится вспомогательный массив, который условно называют **массивом-алфавитом** — обозначим его $C$. Индексами массива $C$ служат сами возможные значения элементов массива $A$, а значением $C[i]$ — количество раз, которое число $i$ встречается в $A$.

### Первая версия алгоритма: простой подсчёт

Первый (наивный) вариант алгоритма состоит из двух проходов:

1. Проходим по массиву $A$ и для каждого элемента $a_j$ увеличиваем счётчик: $C[a_j] \mathrel{+}= 1$.
2. После этого прохода $C[i]$ содержит количество чисел, равных $i$, во всём массиве $A$.
3. Чтобы получить отсортированный массив, проходим по $C$ по возрастанию индекса $i$ и для каждого $i$ записываем в $A$ значение $i$ ровно $C[i]$ раз подряд.

:::example
Пусть дан массив $A = [4, 2, 2, 8, 3, 3, 1]$, значения лежат в диапазоне от $1$ до $8$.

1. Обнуляем массив $C$ размера $8$: $C = [0,0,0,0,0,0,0,0]$.
2. Проходим по $A$ и считаем вхождения:
   - встретили $4$ → $C[4]{+}{+}$
   - встретили $2$ → $C[2]{+}{+}$
   - встретили $2$ → $C[2]{+}{+}$
   - встретили $8$ → $C[8]{+}{+}$
   - встретили $3$ → $C[3]{+}{+}$
   - встретили $3$ → $C[3]{+}{+}$
   - встретили $1$ → $C[1]{+}{+}$

   Получаем $C = [1,2,2,0,1,0,0,1]$ (индексы $1..8$).
3. Проходим по $C$ слева направо и выписываем каждое $i$ ровно $C[i]$ раз:
   $1$ (один раз), $2$ (два раза), $3$ (два раза), $4$ (один раз), $8$ (один раз).

   Итог: $A = [1, 2, 2, 3, 3, 4, 8]$ — массив отсортирован.
:::

### Проблема первой версии: массив становится неустойчивым

На первый взгляд алгоритм работает быстро и просто, однако у него есть существенный недостаток.

:::warning
Первая версия сортировки подсчётом сортирует **только числа**, а не объекты. Если элементы массива — это не просто числа, а, например, записи (объекты) с ключом, по которому идёт сортировка, то при выписывании значений из $C$ обратно в $A$ мы теряем сами объекты и оставляем только их ключи. Иными словами, такая сортировка **вообще не является устойчивой** — она не просто «не сохраняет порядок одинаковых ключей», а разрушает связанные с ключами данные полностью.
:::

Устойчивость сортировки — это свойство сохранять относительный порядок элементов с одинаковыми ключами. Первая версия не даёт даже такой возможности, поскольку восстанавливает только сами числа, а исходные объекты, которые за ними стояли, никак не запоминаются.

Чтобы решить эту проблему, нужна вторая, более аккуратная версия алгоритма.

### Вторая версия: массив префиксных сумм

Чтобы не терять объекты и сделать сортировку устойчивой, вместо прямого выписывания значений используют **массив префиксных сумм**.

:::meaning
**Префиксная сумма** массива $C$ в позиции $i$ — это сумма $C[0] + C[1] + \dots + C[i]$, то есть количество элементов массива $A$, значения которых **не превышают** $i$.
:::

Построение и использование:

1. Как и раньше, строим массив $C$: $C[i]$ — количество элементов, равных $i$.
2. Строим на основе $C$ массив префиксных сумм $P$:
$$
P[i] = \sum_{k \le i} C[k]
$$
Значение $P[i]$ показывает, на какую позицию (считая с $1$) в отсортированном массиве должен встать **последний** по порядку элемент со значением $i$.
3. Заводим новый массив (результат) той же длины, что и $A$.
4. Проходим по исходному массиву $A$ **справа налево** — от последнего элемента к первому. Для текущего элемента $a_j = i$:
   - кладём $a_j$ (весь объект целиком, а не только число) на позицию $P[i] - 1$ результирующего массива (индексация с нуля);
   - уменьшаем $P[i]$ на единицу — освобождая эту позицию для следующего (более раннего в исходном массиве) элемента с тем же значением $i$.

:::formula
$$
P[i] = C[0] + C[1] + \dots + C[i]
$$
Префиксная сумма показывает конечную (последнюю) позицию для значения $i$ в отсортированном массиве.
:::

### Почему идём справа налево: свойство устойчивости

:::note
Важно понимать, зачем именно нужен обход **справа налево**, а не слева направо.
:::

Значение $P[i]$ указывает на позицию для *последнего* элемента с ключом $i$. Если мы идём по исходному массиву справа налево, то первым мы встречаем элемент, который в исходном массиве стоял позже всех остальных элементов с тем же ключом — и именно его мы ставим на последнюю отведённую для ключа $i$ позицию (то есть $P[i]-1$), после чего уменьшаем $P[i]$.

Далее, двигаясь дальше влево, мы встречаем элементы с тем же ключом $i$, которые в исходном массиве стояли раньше — и они попадают на позиции, идущие **перед** уже размещённым элементом (так как $P[i]$ каждый раз уменьшается на единицу). В результате относительный порядок элементов с одинаковым ключом сохраняется: кто раньше стоял в $A$, тот раньше окажется и в отсортированном массиве.

:::warning
Если обходить массив $A$ слева направо, а не справа налево, устойчивость нарушится: элементы с одинаковым ключом поменяются местами относительно исходного порядка, потому что первый встреченный элемент с ключом $i$ займёт *последнюю* отведённую для $i$ позицию, а не первую.
:::

### Доказательство временной сложности

Пусть $n$ — количество элементов в массиве $A$, а $k$ — размер алфавита (диапазона возможных значений).

Алгоритм состоит из следующих проходов:

1. Нахождение диапазона значений (минимума и максимума) — один проход по $A$: $O(n)$.
2. Заполнение массива $C$ (подсчёт вхождений) — один проход по $A$: $O(n)$.
3. Построение массива префиксных сумм $P$ по $C$ — один проход по $C$: $O(k)$.
4. Проход по $A$ справа налево с расстановкой элементов в результирующий массив: $O(n)$.

Суммарное время работы:
$$
O(n) + O(n) + O(k) + O(n) = O(n + k)
$$

:::remember
Временная сложность сортировки подсчётом: $O(n+k)$, где $n$ — размер массива, $k$ — размер алфавита (диапазон значений). Дополнительная память тоже $O(n+k)$ — на массивы $C$, $P$ и результирующий массив.
:::

Отсюда видно ключевую особенность алгоритма: он эффективен только тогда, когда алфавит $k$ сравним по порядку с $n$ (например, $k = O(n)$). Если $k$ значительно больше $n$ (например, сортируются произвольные 32-битные числа), алгоритм становится невыгодным — отсюда возникает потребность в поразрядной сортировке (см. ниже).

### Определение алфавита сортировки

Перед тем как строить массив $C$, нужно знать его размер — то есть диапазон значений элементов $A$.

1. Проходим по массиву $A$ один раз и находим одновременно $\max$ и $\min$ среди всех элементов — это делается за $O(n)$.
2. Размер алфавита вычисляется как
$$
k = \max - \min + 1
$$
3. При этом индексы массива $C$ удобно сдвигать на $-\min$, чтобы значение $\min$ соответствовало индексу $0$, а значение $\max$ — индексу $k-1$; это позволяет работать и с отрицательными числами.

:::example
Разберём пошагово поиск алфавита для массива $A = [-3, 5, 0, 5, -1]$.

1. Проходим по массиву и одновременно обновляем минимум и максимум: $\min = -3$, $\max = 5$.
2. Размер алфавита: $k = 5 - (-3) + 1 = 9$.
3. Индекс элемента со значением $x$ в массиве $C$ будет равен $x - \min$, то есть, например, значению $-3$ соответствует индекс $0$, а значению $5$ — индекс $8$.
:::

### Пример кода (C++)

Ниже приведена вторая версия алгоритма — с массивом префиксных сумм, обходом справа налево и поддержкой произвольного диапазона значений (не обязательно с $\min = 0$):

```cpp
#include <vector>
#include <algorithm>
using namespace std;

vector<int> countingSort(const vector<int>& a) {
    int n = a.size();
    if (n == 0) return a;

    // 1. Находим диапазон значений (алфавит)
    int mn = a[0], mx = a[0];
    for (int x : a) {
        mn = min(mn, x);
        mx = max(mx, x);
    }
    int k = mx - mn + 1;

    // 2. Считаем количество вхождений каждого значения
    vector<int> c(k, 0);
    for (int x : a) {
        c[x - mn]++;
    }

    // 3. Строим массив префиксных сумм
    for (int i = 1; i < k; i++) {
        c[i] += c[i - 1];
    }

    // 4. Проходим справа налево и расставляем элементы
    vector<int> result(n);
    for (int i = n - 1; i >= 0; i--) {
        int key = a[i] - mn;
        c[key]--;              // освобождаем последнюю доступную позицию для key
        result[c[key]] = a[i]; // кладём элемент на эту позицию
    }

    return result;
}
```

:::note
В коде массив `c` используется дважды с разным смыслом: сначала как массив количества вхождений, а после построения префиксных сумм — как массив «указателей» на следующую свободную позицию для каждого ключа. Это экономит память — не нужен отдельный массив `p`.
:::

## Поразрядная (цифровая) сортировка

### Идея алгоритма

Сортировка подсчётом эффективна, только когда алфавит $k$ не слишком велик. Если сортируются, например, числа с большим диапазоном значений, использовать её напрямую невыгодно — массив $C$ окажется слишком большим.

Решение — сортировать числа не целиком, а **по разрядам (цифрам)**, применяя устойчивую сортировку (обычно — сортировку подсчётом) к каждому разряду по очереди.

:::meaning
**Поразрядная (цифровая) сортировка** — способ сортировки чисел, при котором числа сортируются последовательно по отдельным разрядам (цифрам), используя устойчивую сортировку на каждом шаге.
:::

Существуют два основных варианта, различающихся порядком, в котором рассматриваются разряды:

- **MSD (Most Significant Digit)** — сортировка начинается со старшего (самого значимого) разряда.
- **LSD (Least Significant Digit)** — сортировка начинается с младшего (наименее значимого) разряда.

### Radix sort (LSD)

Наиболее распространённый вариант — **LSD radix sort**: сортировка начинается с последней (младшей) цифры и постепенно переходит к более старшим разрядам.

Алгоритм:

1. Определяем максимальное число разрядов $d$ среди всех чисел массива (по числу с наибольшим количеством цифр).
2. Для каждого разряда, начиная с младшего ($1$-го) и заканчивая старшим ($d$-м):
   - применяем **устойчивую** сортировку подсчётом ко всем числам массива, используя в качестве ключа только текущий разряд (цифру).
3. После прохода по всем $d$ разрядам массив оказывается полностью отсортированным.

:::warning
Ключевое условие корректности radix sort — сортировка на каждом шаге должна быть **устойчивой**. Если использовать неустойчивую сортировку хотя бы на одном из разрядов, порядок, установленный по младшим разрядам на предыдущих шагах, может быть разрушен, и итоговый результат окажется неверным.
:::

:::example
Разберём пошагово LSD radix sort для чисел $A = [170, 45, 75, 90, 802, 24, 2, 66]$ (максимум $3$ разряда, $d = 3$).

1. **Сортировка по разряду единиц** (последняя цифра):
   ключи: $170{\to}0,\ 45{\to}5,\ 75{\to}5,\ 90{\to}0,\ 802{\to}2,\ 24{\to}4,\ 2{\to}2,\ 66{\to}6$.
   После устойчивой сортировки по этому разряду:
   $[170, 90, 802, 2, 24, 45, 75, 66]$.
2. **Сортировка по разряду десятков**:
   ключи: $170{\to}7,\ 90{\to}9,\ 802{\to}0,\ 2{\to}0,\ 24{\to}2,\ 45{\to}4,\ 75{\to}7,\ 66{\to}6$.
   После устойчивой сортировки по этому разряду (сохраняя порядок равных ключей из предыдущего шага):
   $[802, 2, 24, 45, 66, 170, 75, 90]$.
3. **Сортировка по разряду сотен**:
   ключи: $802{\to}8,\ 2{\to}0,\ 24{\to}0,\ 45{\to}0,\ 66{\to}0,\ 170{\to}1,\ 75{\to}0,\ 90{\to}0$.
   После устойчивой сортировки по этому разряду:
   $[2, 24, 45, 66, 75, 90, 170, 802]$.

   Массив полностью отсортирован.
:::

### Разница между MSD и LSD

| Признак | LSD (с младшего разряда) | MSD (со старшего разряда) |
|---|---|---|
| Порядок разрядов | от младшего к старшему | от старшего к младшему |
| Требование к устойчивости | обязательна на каждом шаге | требуется отдельная обработка групп |
| Типичная реализация | итеративная, простая | рекурсивная (сортировка внутри «корзин» по следующему разряду) |

:::note
При MSD-сортировке после разбиения чисел по старшему разряду на группы («корзины») каждая группа сортируется рекурсивно по следующему разряду — то есть MSD естественно устроен рекурсивно, в отличие от LSD, где достаточно простого цикла по разрядам.
:::

### Временная сложность Radix Sort

Если $d$ — количество разрядов, а $k$ — размер алфавита одного разряда (например, $k=10$ для десятичных цифр), то каждый из $d$ проходов сортировки подсчётом занимает $O(n+k)$. Суммарно:

$$
O\big(d \cdot (n + k)\big)
$$

:::remember
Временная сложность radix sort: $O(d(n+k))$, где $d$ — число разрядов, $n$ — размер массива, $k$ — размер алфавита одного разряда. Если $d$ и $k$ считать константами (например, для чисел ограниченной длины в фиксированной системе счисления), сложность фактически линейна: $O(n)$.
:::
