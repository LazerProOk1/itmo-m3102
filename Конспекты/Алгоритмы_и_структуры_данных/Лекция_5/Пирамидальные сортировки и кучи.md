# Алгоритмы и структуры данных. Лекция 5. Пирамидальные сортировки

Лекция продолжает тему сортировок. Сначала мы вспоминаем сортировку выбором и видим, в чём её слабое место. Затем разбираем структуру данных **пирамиду (кучу)**, которая позволяет находить максимум гораздо быстрее, и строим на ней **пирамидальную сортировку**.

## Сортировка выбором

:::meaning
**Сортировка выбором** (в варианте с максимумом) на каждом шаге находит наибольший элемент среди ещё не отсортированных и перемещает его в конец неотсортированной части массива. После этого неотсортированная часть становится на один элемент короче.
:::

Псевдокод (индексация с нуля, `end` — последняя позиция неотсортированной части):

```python
def selection_sort(a):
    n = len(a)
    for end in range(n - 1, 0, -1):
        max_i = 0
        for j in range(1, end + 1):
            if a[j] > a[max_i]:
                max_i = j
        a[max_i], a[end] = a[end], a[max_i]
```

Как это работает на массиве: пошаговое выполнение на небольшом примере. Зелёным помечаются элементы, уже вставшие на окончательные места.

```array
title: Сортировка выбором (максимум уходит в конец)
[5, 2, 9, 1, 7]
pointers: j, m
code:
for (let end = a.length - 1; end > 0; end--) {
  let m = 0;
  for (let j = 1; j <= end; j++) {
    if (a[j] > a[m]) m = j;
  }
  swap(a, m, end);
  done(end, a.length - 1);
}
done(0, a.length - 1);
```

:::example
**Оценка времени работы.** Для массива из $n$ элементов:
1. Первый проход ищет максимум среди $n$ элементов — это $n - 1$ сравнение.
2. Второй проход — среди $n - 1$ элементов, то есть $n - 2$ сравнения, и так далее.
3. Общее число сравнений: $(n-1) + (n-2) + \dots + 1 = \dfrac{n(n-1)}{2}$.

Значит, сортировка выбором **квадратична**: $O(n^2)$.
:::

:::note
Слабое место алгоритма: каждый новый максимум ищется «с нуля» полным просмотром. Результаты сравнений, сделанных на предыдущих проходах, нигде не сохраняются. Идея пирамиды — сохранить эту информацию в структуре данных.
:::

## Мотивация: чемпионат РПЛ

Чтобы понять, как можно искать максимумы быстрее, рассмотрим два формата спортивного турнира для $n$ команд. Матч здесь — это сравнение двух элементов.

### Круговая система

В чемпионате РПЛ каждая команда играет с каждой дважды: на своём поле и на поле соперника. Всего проводится $n(n-1)$ матчей, то есть порядка $n^2$. Победителя находят по сумме очков.

Победитель определяется за $O(n^2)$ сравнений. Это тот же порядок, что у сортировки выбором.

### Кубковая система

В кубковой системе команды играют на вылет, и победитель определяется примерно за $n$ матчей (точнее, за $n - 1$: каждый матч выбивает ровно одну команду, а в живых должна остаться одна).

Пример турнира из 8 команд (A — победитель):

```tree
Финал: A — E
  Полуфинал: A — C
    Четвертьфинал: A — B
    Четвертьфинал: C — D
  Полуфинал: E — G
    Четвертьфинал: E — F
    Четвертьфинал: G — H
```

Победитель найден за $O(n)$, но нужно ещё определить вторую, третью команды и так далее:

- Чтобы определить **вторую** команду, достаточно сыграть ещё порядка $\log n$ игр. Вторая команда обязательно среди тех, кто проиграл победителю напрямую. В примере это B, C и E, а таких команд порядка $\log n$ (по одной на каждый тур, который прошёл победитель).
- Для **третьей** команды нужно ещё порядка $\log n$ игр, и так далее.

Для всех $n$ мест в сумме получается $O(n) + n \cdot O(\log n) = O(n \log n)$.

:::warning
Второе место не обязательно занимает проигравший в финале. Команда, проигравшая победителю раньше, могла быть сильнее финалиста. Поэтому сравниваются **все** команды, проигравшие победителю напрямую.
:::

### Причём здесь алгоритмы

Кубковая сетка — это дерево, в котором хранятся результаты уже сыгранных матчей. Благодаря этому следующий «победитель» находится не полным перебором, а за $O(\log n)$. Именно такую структуру и представляет собой пирамида.

## Что такое пирамида (куча)

### Терминология

Слова **пирамида**, **куча** и **heap** обозначают одну и ту же структуру данных, и лучше воспринимать их как синонимы. Дополнительное уточнение — **бинарность**: речь идёт о *бинарной* пирамиде (бинарной куче), то есть о бинарном дереве, обладающем определёнными свойствами.

### Дерево и родители

Устройство дерева удобно понимать на аналогии с семьёй. У каждого человека есть ровно один родитель, который его родил, — мама. Так и в дереве: **у каждого узла (кроме корня) ровно один родитель**.

Родители «принимают решение», сколько детей иметь. В общем случае у узла может быть 0 детей или несколько ($n$). В **бинарном** дереве у узла не больше двух детей.

### Завершённое бинарное дерево

:::meaning
**Завершённое бинарное дерево** — бинарное дерево, в котором заполнены все слои, кроме, возможно, последнего. Последний слой заполняется слева направо без пропусков.
:::

Именно завершённость позволяет хранить дерево в массиве без пустых мест (см. следующий раздел).

### Макс-куча и мин-куча

:::meaning
**Макс-куча** — завершённое бинарное дерево, в котором значение каждого узла **не меньше** значений его детей. Наибольший элемент находится в корне.

**Мин-куча** — завершённое бинарное дерево, в котором значение каждого узла **не больше** значений его детей. Наименьший элемент находится в корне.
:::

### Примеры куч и не куч

**Макс-куча:**

```tree
9
  7
    3
    5
  8
    6
    4
```

**Мин-куча:**

```tree
1
  3
    5
    4
  2
```

**Не куча — нарушен порядок значений.** Узел 5 меньше своего ребёнка 9, поэтому это не макс-куча:

```tree
5
  9
    1
    2
  3
```

**Не куча — дерево не завершено.** Порядок значений соблюдён, но узел 7 не имеет детей, а у узла 8 есть ребёнок. Последний слой заполнен не слева направо:

```tree
9
  7
  8
    3
```

### Свойства пирамиды

- Наибольший элемент макс-кучи (наименьший у мин-кучи) всегда находится в корне.
- Поддерево любого узла само является кучей.
- Дерево завершено, поэтому его высота порядка $\log n$. Отсюда логарифмическое время основных операций.

:::warning
Куча — **не** полностью упорядоченная структура. Она гарантирует порядок только между узлом и его детьми. Между элементами разных поддеревьев никакого порядка нет. Например, в макс-куче выше элемент 7 из левого поддерева больше элемента 6 из правого, а элемент 5 из левого поддерева меньше того же 6.
:::

## Пирамида на массиве

Завершённое бинарное дерево удобно хранить в обычном массиве: узлы записываются в массив слой за слоем, слева направо. Тогда положение родителя и детей вычисляется по индексу.

Пример: дерево из раздела выше как массив.

```array
[9, 7, 8, 3, 5, 6, 4]
```

### Формулы для узла с индексом i

Индексация начинается с нуля, $n$ — число элементов:

:::formula
- левый ребёнок: $2i + 1$
- правый ребёнок: $2i + 2$
- родитель: $\left\lfloor \dfrac{i - 1}{2} \right\rfloor$
:::

Ребёнок существует, только если его индекс меньше $n$.

:::example
Проверим формулы на массиве `[9, 7, 8, 3, 5, 6, 4]` ($n = 7$) для узла $i = 1$ (значение 7):
1. Левый ребёнок: $2 \cdot 1 + 1 = 3$, значение 3.
2. Правый ребёнок: $2 \cdot 1 + 2 = 4$, значение 5.
3. Родитель: $\lfloor (1 - 1)/2 \rfloor = 0$, значение 9.

Это совпадает с деревом: у 7 дети 3 и 5, а родитель 9.
:::

### Сколько листьев, если известно общее число узлов

Лист — узел без детей. Узел $i$ имеет детей, только если $2i + 1 < n$, то есть $i < \dfrac{n - 1}{2}$. Поэтому внутренние узлы — это узлы с индексами $0, 1, \dots, \lfloor n/2 \rfloor - 1$, а **листья — узлы с индексами от $\lfloor n/2 \rfloor$ до $n - 1$**.

:::remember
Из $n$ узлов кучи листьев $\left\lceil \dfrac{n}{2} \right\rceil$, то есть примерно половина. Внутренних узлов $\left\lfloor \dfrac{n}{2} \right\rfloor$.
:::

:::example
Для $n = 7$: внутренние узлы — индексы 0, 1, 2 (три узла, $\lfloor 7/2 \rfloor = 3$), листья — индексы 3, 4, 5, 6 (четыре узла, $\lceil 7/2 \rceil = 4$). Для $n = 6$: внутренние — 0, 1, 2, листья — 3, 4, 5 (по три).
:::

## Пирамидальная сортировка

### Идея: сортировка выбором на максимальной куче

В макс-куче максимум находится в корне, то есть найти его можно сразу. Тогда сортировку выбором можно организовать так:

1. Превратить массив в макс-кучу.
2. Обменять корень (максимум) с последним элементом кучи. Максимум встал на своё итоговое место.
3. Считать кучу короче на один элемент (последний элемент в неё больше не входит).
4. Восстановить свойство кучи — «просеять» новый корень вниз.
5. Повторять шаги 2–4, пока в куче не останется один элемент.

Следующий максимум снова оказывается в корне. Как и в кубковой системе, его не нужно искать заново: информация о сравнениях уже хранится в структуре кучи.

### Просеивание вниз (siftdown)

:::meaning
**Просеивание вниз** (`siftdown`) восстанавливает свойство кучи, если оно нарушено только в одном узле $i$ (его значение может быть меньше значений детей, а оба поддерева уже являются кучами).

Алгоритм: пока у узла есть дети, выбираем **большего** из детей. Если значение узла меньше значения этого ребёнка, обмениваем их и переходим вниз к ребёнку. Иначе останавливаемся.
:::

```diagram
A: round "Узел i"
B: diamond "Есть дети?"
C: box "Выбрать большего ребёнка"
D: diamond "Узел меньше ребёнка?"
E: box "Обменять с ребёнком, перейти к нему"
F: round "Конец"
A -> B
B -> F : Нет
B -> C : Да
C -> D
D -> E : Да
D -> F : Нет
E -> B
```

```python
def sift_down(a, i, n):
    # n — текущий размер кучи
    while True:
        left = 2 * i + 1
        right = 2 * i + 2
        largest = i
        if left < n and a[left] > a[largest]:
            largest = left
        if right < n and a[right] > a[largest]:
            largest = right
        if largest == i:
            break
        a[i], a[largest] = a[largest], a[i]
        i = largest
```

:::warning
При просеивании нужно выбирать именно **большего** из двух детей. Если обменяться с меньшим, он станет родителем большего, и свойство кучи нарушится.
:::

Каждый обмен опускает элемент на один уровень вниз, а высота дерева порядка $\log n$, поэтому одно просеивание стоит $O(\log n)$.

### Алгоритм целиком

```python
def heap_sort(a):
    n = len(a)
    # 1. Построение макс-кучи
    for i in range(n // 2 - 1, -1, -1):
        sift_down(a, i, n)
    # 2. Извлечение максимумов
    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)
```

Первый цикл идёт от $n/2$ до 0 и запускает `siftdown` для каждого узла (подробнее — в разделе про построение кучи). Второй цикл — это сортировка выбором, где максимум берётся из корня.

Пошаговое выполнение (сначала строится куча, затем максимумы переносятся в конец):

```array
title: Пирамидальная сортировка
[5, 2, 9, 1, 7, 3]
pointers: i, big
print: last
code:
function siftDown(i, n) {
  while (2 * i + 1 < n) {
    let big = 2 * i + 1;
    if (big + 1 < n && a[big + 1] > a[big]) big = big + 1;
    if (a[i] >= a[big]) return;
    swap(a, i, big);
    i = big;
  }
}
let n = a.length;
for (let s = Math.floor(n / 2) - 1; s >= 0; s--) siftDown(s, n);
for (let end = n - 1; end > 0; end--) {
  swap(a, 0, end);
  siftDown(0, end);
  done(end, n - 1);
}
done(0, n - 1);
```

:::example
Разберём вручную сортировку массива `[5, 2, 9, 1, 7, 3]` ($n = 6$).

**Построение кучи** (индексы от $n/2 - 1 = 2$ до 0):
1. $i = 2$: значение 9, единственный ребёнок (индекс 5) равен 3. Так как $9 \ge 3$, обмена нет.
2. $i = 1$: значение 2, дети 1 и 7. Больший — 7, $2 < 7$, обмениваем: `[5, 7, 9, 1, 2, 3]`. Дальше у позиции 4 детей нет.
3. $i = 0$: значение 5, дети 7 и 9. Больший — 9, обмениваем: `[9, 7, 5, 1, 2, 3]`. Теперь 5 стоит в позиции 2, её единственный ребёнок равен 3, $5 \ge 3$ — стоп.

Получилась макс-куча `[9, 7, 5, 1, 2, 3]`.

**Извлечение максимумов:**
1. Обмен корня с последним элементом: `[3, 7, 5, 1, 2 | 9]`. Просеиваем 3 в куче из 5 элементов: больший ребёнок 7, обмен — `[7, 3, 5, 1, 2 | 9]`. У 3 дети 1 и 2, $3 \ge 2$ — стоп.
2. Обмен: `[2, 3, 5, 1, 7 | 9]`. Просеиваем 2 в куче из 4 элементов: больший ребёнок 5, обмен — `[5, 3, 2, 1 | 7, 9]`.
3. Обмен: `[1, 3, 2, 5 | 7, 9]`. Просеиваем 1 в куче из 3 элементов: больший ребёнок 3, обмен — `[3, 1, 2 | 5, 7, 9]`.
4. Обмен: `[2, 1, 3 | 5, 7, 9]`. Просеиваем 2 в куче из 2 элементов: ребёнок 1, $2 \ge 1$ — стоп.
5. Обмен: `[1, 2 | 3, 5, 7, 9]`. Остался один элемент.

Результат: `[1, 2, 3, 5, 7, 9]`. Вертикальная черта отделяет кучу от уже отсортированной части.
:::

## Построение пирамиды за O(n)

### Эффективное построение

Чтобы построить кучу из произвольного массива, достаточно пройти по узлам **снизу вверх**, от последнего внутреннего узла к корню, и для каждого запустить `siftdown`:

```python
for i in range(n // 2 - 1, -1, -1):
    sift_down(a, i, n)
```

:::note
Листья (индексы от $\lfloor n/2 \rfloor$ до $n - 1$) просеивать не нужно: у них нет детей, и каждый лист уже является кучей из одного элемента. Поэтому цикл начинается с середины массива. Если запустить `siftdown` и для индекса $n/2$, ничего не изменится: это лист.
:::

Почему порядок «снизу вверх» корректен: когда мы просеиваем узел $i$, оба его поддерева уже являются кучами, то есть `siftdown` применяется именно в тех условиях, для которых он написан.

### Почему это O(n), а не O(n log n)

Оценка «$n/2$ узлов умножить на $O(\log n)$ за каждый» даёт $O(n \log n)$, но она слишком грубая. Просеивание узла стоит не $\log n$, а порядка его **высоты** $h$ (расстояния до самого дальнего листа):

1. Узлов высоты $h$ не более $\left\lceil \dfrac{n}{2^{h+1}} \right\rceil$. Больше всего узлов у листьев, меньше всего у корня.
2. Суммарная стоимость: $\displaystyle\sum_{h=0}^{\log n} \dfrac{n}{2^{h+1}} \cdot O(h) = O\!\left(n \sum_{h=0}^{\infty} \dfrac{h}{2^h}\right)$.
3. Ряд $\displaystyle\sum_{h=0}^{\infty} \dfrac{h}{2^h}$ сходится (его сумма равна 2), то есть это константа.

Итого построение кучи занимает $O(n)$.

:::remember
Построение кучи снизу вверх: $O(n)$. Основная часть узлов находится у самых листьев, где просеивание дешёвое. Только единицы узлов вблизи корня просеиваются на полную глубину.
:::

```quiz
title: Проверка: построение кучи за линейное время

- [ ] $O(n^2)$
```

## Асимптотики

Сводка по лекции:

| Действие | Время |
|---|---|
| Сортировка выбором (поиск максимума просмотром) | $O(n^2)$ |
| Одно просеивание вниз (`siftdown`) | $O(\log n)$ |
| Построение кучи из массива | $O(n)$ |
| Извлечение всех $n$ максимумов из кучи | $n \cdot O(\log n) = O(n \log n)$ |
| Пирамидальная сортировка целиком | $O(n) + O(n \log n) = O(n \log n)$ |

Итоговая оценка определяется второй фазой: линейное построение кучи на её фоне незаметно. Пирамидальная сортировка работает за $O(n \log n)$ против $O(n^2)$ у сортировки выбором. Это та же оценка, что и у кубковой системы при определении всех мест.

:::remember
Пирамидальная сортировка: **$O(n \log n)$**. Построение кучи — $O(n)$, затем $n$ извлечений максимума по $O(\log n)$.
:::
