# Итеративный Merge Sort. Быстрая сортировка

## Итеративный Merge Sort

### Идея алгоритма

Обычная (рекурсивная) сортировка слиянием делит массив пополам «сверху вниз», пока не останутся куски из одного элемента, а затем сливает их обратно. **Итеративная** версия обходится без рекурсии и работает «снизу вверх»:

1. Сначала каждый элемент массива считается отдельным отсортированным блоком длины $1$.
2. Соседние блоки **попарно объединяются** (сливаются) в отсортированные блоки длины $2$.
3. Затем соседние блоки длины $2$ объединяются в блоки длины $4$, потом длины $8$ и так далее.
4. Процесс останавливается, когда размер блока достигает длины массива $n$ или превышает её, — тогда весь массив представляет собой один отсортированный блок.

:::meaning
**Слияние (merge)** — объединение двух уже отсортированных подмассивов в один отсортированный. Именно эта операция здесь «делает всю работу»: сама по себе сортировка — это многократное слияние блоков возрастающего размера.

**Размер блока** $s$ — длина каждого из двух сливаемых блоков на текущем проходе. После прохода блоки имеют длину $2s$ (кроме, возможно, последнего — он может оказаться короче).
:::

:::note
Каждый блок из одного элемента отсортирован тривиально. Поэтому итеративной версии не нужно «спускаться» вниз по рекурсии — она сразу начинает с блоков длины $1$ и поднимается вверх.
:::

### Псевдокод

Основной цикл состоит из двух вложенных циклов: внешний перебирает размер блока $s$ (он удваивается на каждом проходе), внутренний проходит по массиву и сливает пары соседних блоков.

```text
n := length(arr)
buf := новый массив длины n

for s := 1; s < n; s *= 2:
    for i := 0; i < n; i += 2 * s:
        if i + s >= n:
            скопировать arr[i .. n) в buf[i .. n)
            continue
        merge(arr[i .. i + s), arr[i + s .. min(i + 2 * s, n)), buf + i)
    swap(arr, buf)
```

Разберём каждую строку.

- **`for s := 1; s < n; s *= 2`** — внешний цикл. Переменная $s$ принимает значения $1, 2, 4, 8, \dots$ и хранит размер **левого** блока пары. Цикл идёт, пока $s < n$: если $s \ge n$, то весь массив уже лежит в одном блоке.
- **`for i := 0; i < n; i += 2 * s`** — внутренний цикл. Переменная $i$ — начало очередной пары блоков. Каждая пара занимает $2s$ позиций, поэтому $i$ увеличивается на $2s$.
- **`arr[i .. i + s)`** — левый блок пары, то есть элементы с индексами от $i$ до $i+s-1$. Запись $[a; b)$ означает полуинтервал: левая граница входит, правая — нет.
- **`arr[i + s .. min(i + 2 * s, n))`** — правый блок пары. Обычно его правая граница равна $i+2s$, но у последней пары она может выйти за пределы массива, поэтому берётся минимум: $\min(i+2s,\, n)$.
- **`if i + s >= n`** — если начало правого блока $i+s$ уже не меньше $n$, то у левого блока нет пары. Сливать нечего, такой блок пропускается (`continue`) и остаётся на проходе без изменений.
- **`merge(..., buf + i)`** — слияние двух блоков с записью результата в буфер, начиная с позиции $i$.
- **`swap(arr, buf)`** — после прохода по всему массиву результат лежит в `buf`; массивы меняются ролями.

:::meaning
**Аргументы `merge` — это указатели** на начало и конец блоков, а не копии подмассивов. Поэтому сами блоки при передаче в `merge` не копируются. Сама операция `merge` работает за $O(n)$: каждый элемент сливаемых блоков записывается в `buf` ровно один раз.

**`swap(arr, buf)` работает за $O(1)$**, потому что меняются местами только указатели на массивы, а не их содержимое.
:::

:::warning
Если блок пропущен по условию `i + s >= n`, его элементы всё равно должны попасть в `buf`: после `swap(arr, buf)` «настоящим» массивом станет `buf`, и несливаемый хвост пропал бы из него. Поэтому такой хвост нужно скопировать в `buf` на своё место.

Ещё две частые ошибки: начинать внешний цикл с $s = 2$ (тогда блоки из одного элемента никогда не сливаются между собой) и записывать правую границу правого блока как $i+2s$ без $\min$ (выход за границы массива).
:::

### Как работает `merge`

Слияние устроено так же, как в рекурсивной версии. Есть два отсортированных блока и два указателя — по одному на начало каждого блока.

1. Сравниваем элементы, на которые указывают указатели.
2. Меньший из них записываем в `buf` на очередную позицию и сдвигаем указатель того блока, из которого он взят.
3. Повторяем, пока один из блоков не закончится.
4. Оставшийся «хвост» другого блока целиком дописываем в `buf` (он уже отсортирован и не меньше всего записанного).

### Пример на массиве $[2;\,5;\,3;\,52;\,1;\,-1448;\,993]$

Здесь $n = 7$. Проходов будет три: $s = 1$, $s = 2$ и $s = 4$; при $s = 8 \ge n$ цикл завершается.

Исходный массив:

```array
title: Исходный массив
[2, 5, 3, 52, 1, -1448, 993]
```

:::example
**Проход 1: $s = 1$** (сливаем блоки длины $1$, пары начинаются в $i = 0, 2, 4, 6$).

1. $i = 0$: левый блок $[0; 1) = \{2\}$, правый $[1; 2) = \{5\}$. Так как $2 < 5$, результат: $2,\, 5$.
2. $i = 2$: левый блок $\{3\}$, правый $\{52\}$. Результат: $3,\, 52$.
3. $i = 4$: левый блок $\{1\}$, правый $\{-1448\}$. Так как $-1448 < 1$, результат: $-1448,\, 1$.
4. $i = 6$: $i + s = 7 \ge n$, пары нет. Элемент $993$ просто переносится в буфер.

Массив после прохода: $[2;\,5;\,3;\,52;\,-1448;\,1;\,993]$.
:::

```array
title: После прохода s = 1
[2, 5, 3, 52, -1448, 1, 993]
```

:::example
**Проход 2: $s = 2$** (блоки длины $2$, пары начинаются в $i = 0, 4$).

1. $i = 0$: левый блок $[0; 2) = \{2, 5\}$, правый $[2; 4) = \{3, 52\}$.
   - Сравниваем $2$ и $3$: берём $2$.
   - Сравниваем $5$ и $3$: берём $3$.
   - Сравниваем $5$ и $52$: берём $5$.
   - Левый блок закончился, дописываем остаток правого: $52$.
   - Результат: $2,\, 3,\, 5,\, 52$.
2. $i = 4$: левый блок $[4; 6) = \{-1448, 1\}$, правый $[6; \min(8, 7)) = [6; 7) = \{993\}$.
   - Сравниваем $-1448$ и $993$: берём $-1448$.
   - Сравниваем $1$ и $993$: берём $1$.
   - Левый блок закончился, дописываем $993$.
   - Результат: $-1448,\, 1,\, 993$.

Массив после прохода: $[2;\,3;\,5;\,52;\,-1448;\,1;\,993]$.
:::

```array
title: После прохода s = 2
[2, 3, 5, 52, -1448, 1, 993]
```

:::example
**Проход 3: $s = 4$** (единственная пара, $i = 0$; следующее $i = 8 \ge n$).

Левый блок $[0; 4) = \{2, 3, 5, 52\}$, правый $[4; \min(8, 7)) = [4; 7) = \{-1448, 1, 993\}$.

| Шаг | Сравниваем | Берём | Записано в `buf` |
|---|---|---|---|
| 1 | $2$ и $-1448$ | $-1448$ | $-1448$ |
| 2 | $2$ и $1$ | $1$ | $-1448,\, 1$ |
| 3 | $2$ и $993$ | $2$ | $-1448,\, 1,\, 2$ |
| 4 | $3$ и $993$ | $3$ | $-1448,\, 1,\, 2,\, 3$ |
| 5 | $5$ и $993$ | $5$ | $-1448,\, 1,\, 2,\, 3,\, 5$ |
| 6 | $52$ и $993$ | $52$ | $-1448,\, 1,\, 2,\, 3,\, 5,\, 52$ |
| 7 | левый блок пуст | дописываем $993$ | $-1448,\, 1,\, 2,\, 3,\, 5,\, 52,\, 993$ |

Массив после прохода: $[-1448;\,1;\,2;\,3;\,5;\,52;\,993]$ — он отсортирован.
:::

```array
title: Результат после прохода s = 4
[-1448, 1, 2, 3, 5, 52, 993]
```

Все три прохода сразу в виде дерева слияний: листья — блоки из одного элемента, корень — весь массив. Указаны полуинтервалы индексов.

```tree
title: Дерево слияний для n = 7
[0; 7)
  [0; 4)
    [0; 2)
      [0; 1)
      [1; 2)
    [2; 4)
      [2; 3)
      [3; 4)
  [4; 7)
    [4; 6)
      [4; 5)
      [5; 6)
    [6; 7)
```

:::note
Блок $[6; 7)$ на первом проходе остаётся без пары и только на втором проходе сливается с блоком $[4; 6)$. Поэтому в нижней части дерева он стоит без «соседа».
:::

### Пошаговое выполнение

Ниже — тот же алгоритм на том же массиве в виде программы. Проходы $s = 1, 2, 4$, внутри них — цикл по началам пар $i$, указатели $l$ и $r$ идут по левому и правому блокам.

:::note
В этой демонстрации слияние блоков выполнено обменами соседних элементов прямо внутри одного массива (без отдельного буфера `buf`), чтобы на экране был виден один массив. Результат на каждом проходе тот же, что и в алгоритме с буфером; структура циклов по $s$ и $i$ — та же.
:::

```array
title: Итеративный Merge Sort
[2, 5, 3, 52, 1, -1448, 993]
pointers: i, l, r
print: last
code:
let n = a.length;
for (let s = 1; s < n; s *= 2) {
  for (let i = 0; i < n; i += 2 * s) {
    let mid = i + s;
    if (mid >= n) continue;
    let hi = Math.min(i + 2 * s, n);
    let l = i;
    let r = mid;
    while (l < r && r < hi) {
      if (a[l] <= a[r]) {
        l++;
      } else {
        let k = r;
        while (k > l) {
          swap(a, k, k - 1);
          k--;
        }
        l++;
        r++;
      }
    }
  }
}
```

### Двоичное представление границ блоков

Границы блоков удобно записывать в двоичном виде (для $n = 7$ хватает трёх бит). Запись «$[a; b)$: $x$; $y$» ниже означает: блок с индексами от $a$ до $b$ не включительно, его начало $a$ и конец $b$ записаны в двоичном виде как $x$ и $y$.

**Проход $s = 1$** (блоки длины $1$):

| Блок | Начало | Конец |
|---|---|---|
| $[0; 1)$ | $000$ | $001$ |
| $[1; 2)$ | $001$ | $010$ |
| $\dots$ | $\dots$ | $\dots$ |

**Проход $s = 2$** (блоки длины $2$):

| Блок | Начало | Конец |
|---|---|---|
| $[0; 2)$ | $000$ | $010$ |
| $[2; 4)$ | $010$ | $100$ |
| $\dots$ | $\dots$ | $\dots$ |

**Проход $s = 4$** (блоки длины $4$):

| Блок | Начало | Конец |
|---|---|---|
| $[0; 4)$ | $000$ | $100$ |
| $[4; 7)$ | $100$ | $111$ |

Теперь посмотрим на **пары**: левый блок и правый блок, которые сливаются друг с другом. Сравним двоичные записи их начал.

| Проход | Размер блока $s$ | Пара блоков | Начало левого | Начало правого | Бит, в котором они различаются |
|---|---|---|---|---|---|
| 1 | $1 = 2^0$ | $[0; 1)$ и $[1; 2)$ | $000$ | $001$ | 1-й (младший) |
| 2 | $2 = 2^1$ | $[0; 2)$ и $[2; 4)$ | $000$ | $010$ | 2-й |
| 3 | $4 = 2^2$ | $[0; 4)$ и $[4; 7)$ | $000$ | $100$ | 3-й |

:::remember
На проходе с размером блока $s = 2^k$ у **начала левого блока пары** в $(k+1)$-м бите (считая от младшего) стоит $0$, а у **начала правого блока пары** в этом же бите стоит $1$. Все остальные младшие биты у обоих начал равны нулю.
:::

:::meaning
Почему так получается. Начала пар на проходе $s = 2^k$ — это числа $i = 0,\, 2s,\, 4s,\, \dots$, то есть кратные $2s = 2^{k+1}$. У таких чисел младшие $k+1$ бит равны нулю. Начало правого блока — это $i + s = i + 2^k$: к числу $i$ прибавляется ровно $2^k$, и поэтому в $(k+1)$-м бите появляется единица.

Значит, по номеру бита можно определить, левый или правый блок в паре: бит равен $0$ — блок левый, бит равен $1$ — блок правый.
:::

:::note
Конец последнего блока не обязан быть «круглым» числом: в блоке $[4; 7)$ конец равен $7 = 111_2 = n$, потому что правая граница берётся как $\min(i+2s,\, n)$.
:::

## Быстрая сортировка (quickSort)

**Быстрая сортировка** (quickSort) — ещё один алгоритм сортировки. Ключевая операция в ней — разбиение массива (partition) относительно выбранного опорного элемента. Существуют две классические схемы разбиения — по фамилиям авторов:

- **схема Хоара (Hoare)**;
- **схема Ломуто (Lomuto)**.

:::meaning
**Схема Хоара** — разбиение с двумя указателями, которые идут навстречу друг другу с концов отрезка и меняют местами элементы, оказавшиеся не на своей стороне.

**Схема Ломуто** — разбиение с одним указателем-сканером, идущим по отрезку слева направо; элементы, не превосходящие опорный, собираются в начале отрезка.
:::

### Общая схема quickSort

Обе схемы встраиваются в один и тот же рекурсивный каркас: выбрать опорный элемент, разбить отрезок на две части относительно него (partition), затем отсортировать части рекурсивно. Схемы различаются тем, **как** выполняется разбиение и **какие отрезки** после него отдаются рекурсии.

Во всех примерах ниже используется один массив $[8;\,3;\,7;\,1;\,9;\,2;\,5]$, границы отрезка — $lo$ и $hi$ (обе включительно).

### Схема Ломуто (Lomuto)

**Опорный элемент** — последний элемент отрезка, $a[hi]$. Указатель $j$ сканирует отрезок слева направо, указатель $i$ отмечает границу: всё левее $i$ строго меньше опорного. Если $a[j]$ меньше опорного, элемент меняется местами с $a[i]$, и граница сдвигается вправо. В конце опорный элемент ставится на место $i$.

```text
partition(lo, hi):
    pivot := a[hi]
    i := lo
    for j := lo; j < hi; j++:
        if a[j] < pivot:
            swap(a[i], a[j])
            i++
    swap(a[i], a[hi])
    return i

quickSort(lo, hi):
    if lo < hi:
        p := partition(lo, hi)
        quickSort(lo, p - 1)
        quickSort(p + 1, hi)
```

:::remember
После разбиения по Ломуто опорный элемент стоит **на своём окончательном месте** $p$. Слева от него — элементы меньше опорного, справа — не меньше. Рекурсия запускается для отрезков $[lo;\, p-1]$ и $[p+1;\, hi]$, сам элемент $a[p]$ в них не входит.
:::

**Одно разбиение по Ломуто** на массиве $[8;\,3;\,7;\,1;\,9;\,2;\,5]$, опорный элемент $5$:

```array
title: Lomuto — одно разбиение
[8, 3, 7, 1, 9, 2, 5]
pointers: i, j
print: last
code:
let lo = 0;
let hi = a.length - 1;
let pivot = a[hi];
let i = lo;
for (let j = lo; j < hi; j++) {
  if (a[j] < pivot) {
    swap(a, i, j);
    i++;
  }
}
swap(a, i, hi);
done(i);
```

:::example
Разберём ход разбиения: опорный элемент $5$, $i = 0$.

1. $j = 0$: $8 < 5$ — ложь. Ничего не делаем.
2. $j = 1$: $3 < 5$ — истина. Меняем $a[0]$ и $a[1]$, получаем $[3;\,8;\,7;\,1;\,9;\,2;\,5]$, $i = 1$.
3. $j = 2$: $7 < 5$ — ложь.
4. $j = 3$: $1 < 5$ — истина. Меняем $a[1]$ и $a[3]$, получаем $[3;\,1;\,7;\,8;\,9;\,2;\,5]$, $i = 2$.
5. $j = 4$: $9 < 5$ — ложь.
6. $j = 5$: $2 < 5$ — истина. Меняем $a[2]$ и $a[5]$, получаем $[3;\,1;\,2;\,8;\,9;\,7;\,5]$, $i = 3$.
7. Цикл закончен. Меняем $a[i] = a[3]$ и опорный $a[6]$: получаем $[3;\,1;\,2;\,5;\,9;\,7;\,8]$. Опорный элемент стоит на месте $3$.

Дальше рекурсивно сортируются отрезки $[0;\,2]$ и $[4;\,6]$.
:::

**Полная сортировка по схеме Ломуто** (разбиение внутри рекурсии; зелёным отмечаются элементы, вставшие на окончательные места):

```array
title: quickSort со схемой Ломуто
[8, 3, 7, 1, 9, 2, 5]
pointers: i, j, lo, hi
print: last
code:
function qs(lo, hi) {
  if (lo < hi) {
    let pivot = a[hi];
    let i = lo;
    for (let j = lo; j < hi; j++) {
      if (a[j] < pivot) {
        swap(a, i, j);
        i++;
      }
    }
    swap(a, i, hi);
    done(i);
    qs(lo, i - 1);
    qs(i + 1, hi);
  }
  if (lo == hi) {
    done(lo);
  }
}
qs(0, a.length - 1);
```

### Схема Хоара (Hoare)

**Опорный элемент** — первый элемент отрезка, $a[lo]$. Два указателя идут навстречу друг другу: $i$ — слева направо, пока элементы меньше опорного; $j$ — справа налево, пока элементы больше опорного. Когда оба остановились, возможны два случая: если $i < j$, найденные элементы стоят не на своей стороне и меняются местами; если $i \ge j$, указатели разошлись, и разбиение закончено, а результатом служит $j$.

```text
partition(lo, hi):
    pivot := a[lo]
    i := lo - 1
    j := hi + 1
    loop:
        do i++ while a[i] < pivot
        do j-- while a[j] > pivot
        if i >= j:
            return j
        swap(a[i], a[j])

quickSort(lo, hi):
    if lo < hi:
        p := partition(lo, hi)
        quickSort(lo, p)
        quickSort(p + 1, hi)
```

:::warning
Результат разбиения по Хоара — граница между двумя частями, а **не место опорного элемента**: после разбиения все элементы отрезка $[lo;\, p]$ не больше опорного, а все элементы отрезка $[p+1;\, hi]$ не меньше него. Поэтому рекурсия запускается для $[lo;\, p]$ и $[p+1;\, hi]$, то есть граница $p$ входит в левую часть. Если по привычке от Ломуто написать $p - 1$ и $p + 1$, элементы будут потеряны.

Опорный элемент в этой записи берётся первым, $a[lo]$. Если взять последний $a[hi]$, то рекурсия может зациклиться на отрезках, которые не уменьшаются.
:::

**Одно разбиение по Хоара** на массиве $[8;\,3;\,7;\,1;\,9;\,2;\,5]$, опорный элемент $8$:

```array
title: Hoare — одно разбиение
[8, 3, 7, 1, 9, 2, 5]
pointers: i, j
print: last
code:
let lo = 0;
let hi = a.length - 1;
let pivot = a[lo];
let i = lo - 1;
let j = hi + 1;
let res = -1;
while (res < 0) {
  do {
    i++;
  } while (a[i] < pivot);
  do {
    j--;
  } while (a[j] > pivot);
  if (i >= j) {
    res = j;
  } else {
    swap(a, i, j);
  }
}
say("указатели разошлись: граница разбиения найдена");
```

:::example
Разберём ход разбиения: опорный элемент $8$, сначала $i = -1$, $j = 7$.

1. Сдвигаем $i$: $i = 0$, и $a[0] = 8 < 8$ — ложь, $i$ остановился на $0$.
2. Сдвигаем $j$: $j = 6$, и $a[6] = 5 > 8$ — ложь, $j$ остановился на $6$.
3. $i < j$, меняем $a[0]$ и $a[6]$: получаем $[5;\,3;\,7;\,1;\,9;\,2;\,8]$.
4. Сдвигаем $i$: элементы $3$, $7$, $1$ меньше $8$, поэтому $i$ доходит до $4$, где $a[4] = 9 \not< 8$.
5. Сдвигаем $j$: $j = 5$, $a[5] = 2 > 8$ — ложь, $j$ остановился на $5$.
6. $i = 4 < j = 5$, меняем $a[4]$ и $a[5]$: получаем $[5;\,3;\,7;\,1;\,2;\,9;\,8]$.
7. Сдвигаем $i$: $i = 5$, $a[5] = 9 \not< 8$. Сдвигаем $j$: $j = 4$, $a[4] = 2 > 8$ — ложь.
8. Теперь $i = 5 \ge j = 4$, указатели разошлись. Результат разбиения: $p = 4$.

Левая часть $[0;\,4] = [5;\,3;\,7;\,1;\,2]$ состоит из элементов не больше $8$, правая $[5;\,6] = [9;\,8]$ — из элементов не меньше $8$. Опорный элемент $8$ оказался в правой части и не обязан стоять на окончательном месте.
:::

**Полная сортировка по схеме Хоара** (разбиение записано прямо в теле рекурсивной функции; зелёным отмечаются отрезки из одного элемента, которые уже стоят на своих местах):

```array
title: quickSort со схемой Хоара
[8, 3, 7, 1, 9, 2, 5]
pointers: i, j, lo, hi
print: last
code:
function qs(lo, hi) {
  if (lo < hi) {
    let pivot = a[(lo + hi) >> 1];
    let i = lo;
    let j = hi;
    let res = -1;
    while (res < 0) {
      while (a[i] < pivot) {
        i++;
      }
      while (a[j] > pivot) {
        j--;
      }
      if (i >= j) {
        res = j;
      } else {
        swap(a, i, j);
        i++;
        j--;
      }
    }
    qs(lo, res);
    qs(res + 1, hi);
  }
  if (lo == hi) {
    done(lo);
  }
}
qs(0, a.length - 1);
```

### Сравнение схем

| | Ломуто | Хоара |
|---|---|---|
| Опорный элемент | последний, $a[hi]$ | первый, $a[lo]$ |
| Указатели | оба идут слева направо ($i$ — граница, $j$ — сканер) | идут навстречу друг другу |
| Что возвращает | индекс опорного элемента $p$ | границу между частями $p$ |
| Опорный элемент после разбиения | стоит на окончательном месте | может оказаться в любой из частей |
| Рекурсивные вызовы | $[lo;\, p-1]$ и $[p+1;\, hi]$ | $[lo;\, p]$ и $[p+1;\, hi]$ |
