title: Тест: Асимптотический анализ алгоритмов
description: Нотации O, Ω, Θ и их арифметика, оценка циклов и рекурсии, инверсии и сортировка вставками, сортировка слиянием, мастер-теорема, линейные сортировки.

? Функция трудоёмкости алгоритма равна $T(n) = 5n^2 + 100n + 7$. Какая оценка является точной (двусторонней) асимптотической оценкой для $T(n)$?
- [ ] $\Theta(n)$ :: Верхней границы вида $c \cdot n$ не существует: квадратичное слагаемое растёт быстрее любого линейного.
- [x] $\Theta(n^2)$ :: Порядок роста задаёт старшее слагаемое, а константу 5 и младшие члены поглощают константы $c_1$ и $c_2$.
- [ ] $\Theta(n^3)$ :: Это верная верхняя граница, но нижней оценки вида $c \cdot n^3$ у функции нет.
explain: Для $\Theta$ функция должна быть зажата между двумя кратными одной и той же $g(n)$ начиная с некоторого $n_0$. Для $g(n) = n^2$ это выполняется.

? Пусть $f(n) = n$. Какие из утверждений верны?
- [x] $f(n) \in O(n^2)$ :: Нотация $O$ — только верхняя граница, она не обязана быть точной.
- [x] $f(n) \in \Theta(n)$ :: Любая функция принадлежит $\Theta$ от самой себя (рефлексивность).
- [ ] $f(n) \in \Theta(n^2)$ :: Для $\Theta$ нужна и нижняя оценка $c \cdot n^2 \le n$, а она нарушается при больших $n$.
- [ ] $f(n) \in \Omega(n^2)$ :: Линейная функция отстаёт от $c \cdot n^2$ при любой константе $c > 0$.
- [ ] $f(n) \in \Omega(n \log n)$ :: Нижняя граница $c \cdot n \log n$ тоже превосходит $n$ при больших $n$.
explain: Верно ровно то, что согласуется с определениями: $O$ означает «не быстрее», $\Omega$ — «не медленнее», $\Theta$ — оба условия сразу.

? Про сортировку вставками говорят: в лучшем случае $O(n)$, в худшем $O(n^2)$. Как связаны нотация $O$ и понятия лучшего и худшего случая?
- [ ] $O$ всегда описывает худший случай, а $\Omega$ — лучший :: Это частая путаница: $O$ не является синонимом худшего случая.
- [ ] У одного алгоритма оценки в лучшем и худшем случаях обязаны совпадать по порядку :: У сортировки вставками они различаются: $O(n)$ и $O(n^2)$.
- [ ] Нотации применяются только к худшему случаю, для лучшего случая они не определены :: Любую из нотаций можно ставить для функции $T(n)$ любого случая.
- [x] Это независимые понятия: нотация описывает форму роста функции $T(n)$, а случай определяет, на каких входах размера $n$ она измеряется :: Поэтому $O$ можно ставить и для лучшего, и для среднего, и для худшего случая.
explain: У алгоритма может быть несколько функций $T(n)$ (по одной на каждый случай), и для каждой отдельно можно указывать $O$, $\Omega$ или $\Theta$.

? Алгоритм сначала выполняет один цикл на $n$ итераций, а затем — два вложенных цикла по $n$ итераций каждый. Какова оценка сложности всего алгоритма?
- [ ] $O(n)$ :: Так оценивается только первый блок.
- [ ] $O(n^3)$ :: Перемножаются оценки вложенных блоков, а блоки, идущие друг за другом, складываются.
- [x] $O(n^2)$ :: Сумма $O(n) + O(n^2)$ определяется более быстро растущим слагаемым.
- [ ] $O(n \log n)$ :: Логарифма здесь нет: ни один из циклов не уменьшает диапазон вдвое.
explain: При последовательных блоках оценки складываются, то есть берётся максимум: $O(n) + O(n^2) = O(n^2)$.

? Какова асимптотическая сложность этого фрагмента?
~~~c
for (i = 1; i <= n; ++i)
    for (j = 0; j < i; ++j) { }
~~~
- [x] $\Theta(n^2)$ :: Внутренний цикл делает $i$ шагов, суммарно $1 + 2 + \dots + n = \frac{n(n+1)}{2}$.
- [ ] $\Theta(n \log n)$ :: Внутренний цикл не делит диапазон пополам, он просто проходит $i$ значений.
- [ ] $\Theta(n)$ :: Внутренний цикл зависит от $i$, поэтому его длина растёт вместе с $n$.
- [ ] $\Theta(n^3)$ :: Три множителя $n$ здесь не набираются: всего два цикла.
explain: Число итераций равно сумме арифметической прогрессии $\frac{n(n+1)}{2}$, а это $\Theta(n^2)$.

? Сколько раз выполнится тело цикла при $n = 16$? Введите целое число.
~~~c
for (s = 1; s < n; s *= 2) { }
~~~
= 4
correct: Переменная $s$ принимает значения 1, 2, 4, 8 — это 4 итерации; при $s = 16$ условие $s < 16$ ложно.
wrong: Считайте значения $s$, при которых $s < 16$: это 1, 2, 4, 8. Значение 16 уже не проходит, итого 4 итерации (в общем случае порядка $\log_2 n$).

? Массив из $n$ элементов почти отсортирован: общее число инверсий равно $Inv(a) = O(n)$. Сколько времени потребует сортировка вставками, если её время работы равно $\Theta(n + Inv(a))$?
- [ ] $\Theta(n^2)$ :: Квадратичное время получается только при порядка $n^2$ инверсий.
- [ ] $\Theta(n \log n)$ :: Формула не содержит логарифмического множителя.
- [ ] Определить нельзя, нужно знать значения элементов :: Достаточно знать число инверсий, оно и задаёт объём сдвигов.
- [x] $\Theta(n)$ :: Каждая инверсия соответствует одному сдвигу, и при $Inv(a) = O(n)$ слагаемое $n + Inv(a)$ имеет порядок $n$.
explain: Время сортировки вставками зависит от степени неупорядоченности массива. Чем меньше инверсий, тем быстрее работа, а при $Inv(a) = 0$ время линейно.

? Какое наибольшее число инверсий может быть в массиве из 10 элементов? Введите целое число.
= 45
correct: Максимум достигается на массиве, отсортированном в обратном порядке, где инверсией является каждая пара: $\frac{10 \cdot 9}{2} = 45$.
wrong: Худший случай — обратный порядок, когда каждая пара индексов $i < j$ образует инверсию. Таких пар $\binom{10}{2} = \frac{10 \cdot 9}{2} = 45$.

? Дерево рекурсивных вызовов сортировки слиянием имеет глубину порядка $\log_2 n$, на каждом уровне слияния суммарно обрабатывают порядка $n$ элементов. Какие утверждения о времени и памяти рекурсии верны?
- [x] Время работы определяется суммарной работой по всем узлам дерева вызовов :: Нужно учесть число вызовов и работу вне рекурсии в каждом из них.
- [x] Память стека вызовов определяется глубиной дерева, а не числом узлов :: В каждый момент живут только вызовы вдоль одного пути от корня до текущего листа.
- [ ] Память стека вызовов пропорциональна общему числу узлов дерева :: Все вызовы одновременно не активны, поэтому число узлов определяет время, а не память стека.
- [ ] Время работы определяется только глубиной дерева :: Глубина не учитывает, сколько вызовов на каждом уровне и сколько работы в каждом.
- [x] Суммарная работа слияний на каждом уровне имеет порядок $O(n)$, поэтому общее время равно $O(n \log n)$ :: Один и тот же вклад $O(n)$ набирается на каждом из $\log_2 n$ уровней.
explain: Время связано с суммарной работой по всем узлам, память стека — с глубиной дерева. Это два разных параметра, и растут они по-разному.

? В итеративной сортировке слиянием внешний цикл `for s := 1; s < n; s *= 2` удваивает размер блока, а внутренний цикл на каждом проходе сливает все пары соседних блоков. Каждый элемент при этом записывается в буфер ровно один раз за проход, а `swap(arr, buf)` стоит $O(1)$. Какова временная сложность алгоритма?
- [ ] $\Theta(n)$ :: Это стоимость одного прохода, а проходов порядка $\log_2 n$.
- [ ] $\Theta(n^2)$ :: Вложенность циклов сама по себе не даёт $n^2$: внешний цикл удваивает $s$, а не увеличивает его на 1.
- [x] $\Theta(n \log n)$ :: Проходов порядка $\log_2 n$, и каждый обрабатывает все $n$ элементов.
- [ ] $\Theta(n \log^2 n)$ :: Лишнего логарифмического множителя нет: слияние блоков линейно по их суммарному размеру.
explain: Внешний цикл выполняется порядка $\log_2 n$ раз, а внутренний вместе со слияниями за один проход работает за $O(n)$. Итого $O(n \log n)$, как и у рекурсивной версии.

? Чему равна асимптотика рекуррентного соотношения $T(n) = 2\,T\!\left(\frac{n}{2}\right) + n^2$?
- [x] $\Theta(n^2)$ :: Здесь $a = 2$, $b = 2$, $c = 2$, а $d = \log_2 2 = 1 < c$: доминирует работа корня дерева.
- [ ] $\Theta(n^2 \log n)$ :: Множитель $\log n$ появляется только при $c = \log_b a$.
- [ ] $\Theta(n \log n)$ :: Такой ответ получился бы при $c = 1$, как в сортировке слиянием.
- [ ] $\Theta(n)$ :: Это ответ $n^{\log_b a}$ для случая, когда доминируют листья, а здесь $c > \log_b a$.
explain: Множитель $\frac{a}{b^c} = \frac{2}{4} < 1$, поэтому работа на каждом следующем уровне убывает, и итог совпадает с работой верхнего уровня: $\Theta(n^2)$.

? Решение соотношения $T(n) = 8\,T\!\left(\frac{n}{2}\right) + n^2$ имеет вид $\Theta(n^p)$. Чему равно $p$? Введите целое число.
= 3
correct: Здесь $d = \log_2 8 = 3$, а $c = 2 < d$. Доминируют листья, и $T(n) = \Theta(n^{3})$.
wrong: Сравните $c = 2$ с $d = \log_2 8 = 3$. Так как $c < d$, множитель $\frac{a}{b^c} = 2 > 1$, работа растёт к листьям, и $T(n) = \Theta(n^d) = \Theta(n^3)$.

? Для каких рекуррентных соотношений мастер-теорема (вид $T(n) = a\,T(n/b) + n^c$) даёт ответ $\Theta(n \log n)$?
- [x] $T(n) = 2\,T(n/2) + n$ :: Здесь $\log_2 2 = 1 = c$, все уровни дерева дают одинаковую работу.
- [ ] $T(n) = 4\,T(n/2) + n$ :: Здесь $\log_2 4 = 2 > c = 1$, поэтому ответ $\Theta(n^2)$.
- [x] $T(n) = 4\,T(n/4) + n$ :: Здесь $\log_4 4 = 1 = c$, значит, случай равенства.
- [ ] $T(n) = T(n/2) + n$ :: Здесь $\log_2 1 = 0 < c = 1$, ответ равен $\Theta(n)$.
- [ ] $T(n) = 2\,T(n/2) + n^2$ :: Здесь $c = 2 > 1 = \log_2 2$, ответ равен $\Theta(n^2)$.
explain: Множитель $\log n$ возникает только когда $c = \log_b a$. Поэтому нужно сравнивать $c$ именно с $\log_b a$, а не $a$ с $b$.

? Можно ли решить соотношение $T(n) = 2\,T(n/2) + n \log n$ напрямую по мастер-теореме?
- [ ] Да, это случай равенства, так как $n \log n$ и $n$ растут примерно одинаково :: Случай равенства требует именно $f(n) \in \Theta(n^{\log_b a})$, а лишний логарифм меняет порядок роста.
- [x] Нет: $f(n)$ растёт быстрее $n^{\log_b a} = n$, но не полиномиально, то есть нет зазора $n^{\varepsilon}$ :: Ни один из трёх случаев не выполняется, это зазор между случаями.
- [ ] Да, это случай доминирования корня, так как $n \log n > n$ :: Для него нужен полиномиальный зазор $n^{\log_b a + \varepsilon}$.
- [ ] Нет, потому что $a = b$ :: Равенство $a = b$ не мешает применению теоремы: в сортировке слиянием тоже $a = b = 2$.
explain: Нужно сравнивать именно порядок роста $f(n)$ с $n^{\log_b a}$. При лишнем логарифмическом множителе стандартная мастер-теорема неприменима, и соотношение решают другим способом, например суммированием по уровням дерева.

? Пусть $n$ — число сортируемых элементов, $k$ — размер алфавита (для поразрядной сортировки — одного разряда), $d$ — число разрядов. Какие утверждения о линейных сортировках верны?
- [x] Сортировка подсчётом работает за $O(n + k)$ :: Складываются проходы по массиву элементов и по массиву счётчиков.
- [ ] Сортировка подсчётом особенно выгодна, когда $k$ намного больше $n$ :: Наоборот, массив счётчиков становится слишком большим, и алгоритм невыгоден.
- [x] Поразрядная сортировка LSD работает за $O(d(n + k))$ :: Выполняется $d$ проходов устойчивой сортировки подсчётом по $O(n + k)$ каждый.
- [ ] Сортировка подсчётом использует $O(1)$ дополнительной памяти :: Нужны массивы $C$, $P$ и результирующий массив, то есть $O(n + k)$.
- [x] При константных $d$ и $k$ поразрядная сортировка работает за $O(n)$ :: Множитель $d(1 + k/n)$ при константных $d$ и $k$ остаётся константой, и общее время линейно.
explain: Сортировка подсчётом хороша при $k = O(n)$. Если диапазон значений велик, числа сортируют по разрядам: время $O(d(n + k))$ при малом $k$ почти линейно.
