# AGENTS.md — как устроен и как разрабатывается репозиторий

Общая инструкция **и для людей, и для ИИ-агентов** (Claude Code, Codex, Cursor и др.): правила работы с git, устройство
кода, договорённости по дизайну и решения, которые уже приняты, — с причинами. Перед тем как менять код, прочитай раздел
про ту часть, которую трогаешь. Поменял устройство — допиши сюда (и проверь, что старые строки не врут: цифры и имена
файлов здесь сверены с кодом). `CLAUDE.md` — только ссылка на этот файл для Claude Code. Что умеют сайты для пользователя —
в [README.md](README.md) и [app/README.md](app/README.md).

Сайт группы М3102 (ИТМО, 1 курс) — **два оформления одного сайта с общими данными**: классическое (статический сайт без
сборки, автор — RedstoneLord) и современное (React + TypeScript + Vite, папка `app/`). Оба живут в одном репозитории
[RedstoneLord/itmo-m3102](https://github.com/RedstoneLord/itmo-m3102) — там же лежат данные группы (конспекты, материалы,
дедлайны, ДЗ) и автоматизация вокруг них. Сайт: https://redstonelord.github.io/itmo-m3102/ (классическое — в корне
адреса, современное — в `/app/`).

## Структура репозитория

В корне — как есть у группы:

- **классический сайт**: `index.html`, `site.css`, `css/`, `js/`, `img/`, `data/`, `Дедлайны/`, `tests/`,
  `manifest.webmanifest`, `sw.js`, `package.json`. Это файлы RedstoneLord: **не править** (см. правила). Нужная нам
  подстройка делается при сборке сайта — `app/src/lib/classicPatch.ts`, а в корне остаётся оригинал;
- **контент группы**: `Конспекты/`, `Материалы/`, `Лабораторные/`, `Записи лекций/`, `Дедлайны/`, `data/*.json` и их
  автоматизация (`tools/`, воркфлоу `lectures-index`, `normalize-names`, `label-deadline-signups`). Формат не менять: его
  читают оба сайта;
- `docs/` (план сервера и др.), `.github/workflows/` (деплой сайта и воркфлоу группы), `README.md`, `AGENTS.md`, `CLAUDE.md`.

Современное оформление целиком в **`app/`**. Поэтому все пути вида `src/…`, `public/…`, `scripts/…`, `e2e/…`,
`package.json`, `.env` ниже — внутри `app/`, а команды `npm` запускать из `app/`.

Готовый сайт собирает `npm run site` (в `app/`, после `npm run build`): классический из корня репозитория → `app/site`,
приложение (`app/dist`) → `app/site/app`; в Pages уходит `app/site`. В dev наоборот: приложение на `/`, классический в
`/classic/` (`app/public/classic`, его делает `npm run dev`). Подробнее — «Переключатель стиля».

## Правила, которые нельзя нарушать

| Правило | Подробности |
|---|---|
| **Коммиты — от имени владельца, без следов ИИ** | `git -c user.name="LazerProOk1" commit …` (email из git-конфига). Никаких `Co-Authored-By` и упоминаний ИИ в коммитах, PR и описаниях. git-конфиг не менять. **Язык сообщений: в этом репозитории — английский** (в личном форке LazerProOk1/itmo-m3102 — русский). |
| **`master` сразу публикуется** | Любой пуш в `master` запускает деплой для всей группы (после зелёных проверок). Перед пушем — полный прогон (см. «Перед каждым коммитом») и `git pull --rebase`: в `master` пишут бот группы и сам RedstoneLord. Пока владелец говорит «не коммить» — не коммитить и не пушить. |
| **Файлы классического сайта — не наши** | Корневые `index.html`, `css/`, `js/`, `site.css` и т. п. принадлежат RedstoneLord. Нужную правку делаем в сборке (`classicPatch.ts`) или предлагаем ему; прямые правки — только по его просьбе. |
| **Секреты — никогда в файлы** | Токены GitHub (PAT) не писать в файлы, коммиты, `.env`, логи и память. PAT пользователя живёт только в браузере (sessionStorage/localStorage, `src/services/github.ts`). |
| **Пароли ИТМО — никогда** | Сайт не принимает пароли студентов ни в каком виде (см. `docs/BACKEND_PLAN.md`). |
| **Контент группы — их формат** | `Конспекты/`, `Материалы/`, `Лабораторные/`, `Записи лекций/`, `Дедлайны/`, `data/`, `img/`, `tools/` и их воркфлоу — данные и автоматизация группы. Формат не менять: оба сайта читают их же. Файлы в корне, которые не материалы (`AGENTS.md`, `CLAUDE.md`, `README.md`…), прячут `isHiddenPath` (приложение) и патч списка скрытых в `classicPatch.ts` (классическое). |
| **Чужой JS — не на лету** | В приложении скрипты с CDN во время работы не грузим: всё — npm-зависимости в сборке (или перенесённый код группы). Классический сайт берёт библиотеки с cdnjs — это его решение, мы его не меняем. |

## Как вести работу в git

**Основной репозиторий — [RedstoneLord/itmo-m3102](https://github.com/RedstoneLord/itmo-m3102), ветка `master`.**
Задачи ведём так:

- **Небольшие исправления** — прямо в `master`: полный прогон локально → `git pull --rebase` → пуш → дождаться деплоя
  (`gh run watch <id> -R RedstoneLord/itmo-m3102 --exit-status`) и проверить сайт глазами. Упали проверки в CI — публикации
  нет, сайт остаётся прежним.
- **Крупное или рискованное** — отдельная ветка в этом же репозитории и PR; влить можно после проверок. Предпросмотра
  ветки нет: публикация только из `master`.
- Контент и воркфлоу группы без нужды не трогаем; воркфлоу бота пушат в `master` сами (`[skip ci]`), поэтому конфликты
  при пуше решаются `git pull --rebase`.

**Личный форк `LazerProOk1/itmo-m3102`** — полигон и архив (деплоит на `lazerprook1.github.io/itmo-m3102`, сообщения
коммитов там на русском). Ветки форка:

| Ветка | Что это |
|---|---|
| `react-app` | история приложения до слияния в репозиторий группы; форк по-прежнему может на ней деплоиться |
| `react-app-dev` | то же, но `app/.env`: `VITE_EDITING=true` — режим редактирования (правка расписания, конспектов, ДЗ с публикацией в GitHub, мемов, ссылок, сроков). В `master` группы режима редактирования нет: там `VITE_EDITING=false` |
| `design-aurora` | эксперимент с ярким оформлением, не деплоится |
| `legacy` | зеркало старого `master` группы (синхронизируется воркфлоу форка) |

Встроенную «Sync fork» на ветках `react-app` и `react-app-dev` форка **не нажимать**: она предложит влить старый сайт
или выбросить наши коммиты.

**Режим редактирования** (только в форке `react-app-dev`). Флаг — `EDITING_ENABLED` в
`src/features/settings/EditModeContext.tsx`. Всё, что меняет общие данные, — за `const { isEditMode } = useEditMode()`.
Личное (учебный план, «сделано», очередь на сдачу) доступно всегда.

**Что поменялось у группы:** `gh api "repos/RedstoneLord/itmo-m3102/commits?per_page=20"`, затем по коду —
`gh api repos/RedstoneLord/itmo-m3102/commits/<sha> -q '.files[].filename'`. Контент сайты подтягивают сами; в код
переносить только изменения форматов и поведения (пример: метку `queue-signup` ставит воркфлоу группы, а не `?labels=` в
ссылке; новая папка конспектов; новые служебные файлы в корне — их прячет `isHiddenPath`).

## Команды, тесты и CI

| Команда | Что делает |
|---|---|
| `npm run dev` | собирает `/classic/` для dev и запускает dev-сервер Vite; `.env` (`app/.env`) читается при старте — после смены перезапустить |
| `npm test` · `test:watch` | Vitest, юнит-тесты `*.test.ts(x)` рядом с кодом |
| `npm run test:e2e` | Playwright: собирает сайт целиком (`build` → `ics` → `site`) и гоняет сценарии по `app/site` (`e2e/`) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run build` · `preview` | типы + сборка приложения в `dist/` · раздать `dist/` локально |
| `npm run size` | бюджет размера сборки (после `build`): `scripts/check-size.mjs` |
| `npm run lighthouse` | Lighthouse по `dist/` (`lighthouserc.json`); на Windows — `CHROME_PATH=путь к msedge.exe` |
| `npm run ics` | календарь-подписка `dist/m3102.ics` из данных группы (`scripts/build-ics.ts` через `tsx`, после `build`) |
| `npm run site` | готовый сайт `app/site`: классический в корне + приложение в `/app/` (`scripts/assemble-classic.ts`, после `build`); `-- --fresh` — со свежими `data/` и `Дедлайны/` (в CI всегда) |
| `npm run classic` | то же для dev: классический сайт из корня → `app/public/classic`; `-- --pull` скачивает файлы его сайта с `master` в корень (нужно только форку и при ручной сверке) |
| `npm run format` · `format:check` | Prettier **только по `src/`** (`.prettierrc.json`: одинарные кавычки, строка до 150, запятые в конце). `AGENTS.md`, `README.md`, `scripts/`, `e2e/` он не проверяет и не трогает — таблицы в md не выравнивать вручную через `prettier --write`. Запускать из `app/`: из корня он не увидит `.prettierignore` и переформатирует то, что трогать нельзя |

В корне (классический сайт): `npm test` — его тесты (`node --test tests/*.mjs`), запуск сайта — `python3 -m http.server`.

**CI** (`.github/workflows/deploy-pages.yml`, пуш в `master` и раз в сутки в 05:00 МСК — ради свежего `.ics` и данных):
Prettier → юнит-тесты → сборка → календарь `m3102.ics` → бюджет размера → готовый сайт (`npm run site -- --fresh`) →
тесты в браузере → Lighthouse → GitHub Pages (Pages настроены на источник «GitHub Actions»). Упало — публикации нет;
трассы упавших e2e — артефакт `e2e-traces`, отчёт Lighthouse — артефакт `lighthouse`. Приложение: `base: './'` +
`HashRouter` `#/schedule` — работает из подпапки `/app/` без 404. Пуш в `.github/workflows/` требует у токена право
`workflow`. Воркфлоу группы (`normalize-names`, `lectures-index`, `label-deadline-signups`) от деплоя независимы.

- **Бюджеты** (`scripts/check-size.mjs`, gzip): JS первой загрузки — порог 215 КБ (сейчас ~208), CSS — 25 КБ
  (~21), одна страница — 220 КБ (самая тяжёлая — конспект, ~200). Тяжёлая библиотека в общем коде сразу видна.
  Lighthouse (3 прогона, медиана): доступность и практики ≥ 0,9 и CLS ≤ 0,1 — ошибка; производительность ≥ 0,5 —
  только предупреждение (эмуляция слабого телефона шумит).
- **Тесты в браузере** (`e2e/`, `playwright.config.ts`) — по готовому сайту (`vite preview --outDir site`): приложение
  на `/app/`, как на Pages (сервис-воркер, чанки, View Transitions). GitHub подменён заглушками `e2e/github.ts` (два
  конспекта: md и PDF, PDF генерируется в коде), остальной интернет обрывается; классическую страницу в тесте
  переключателя подменяет заглушка. Часы — 1 октября 2026, 12:00 МСК. Семь сценариев: переход с главной на предмет
  (замер внутри страницы, < 1 с), поиск по тексту конспекта, неделя расписания, PDF, офлайн, переключатель стиля,
  телефон (свайп, нет горизонтальной прокрутки; проект `phone`, тег `@phone`). Локально — Edge
  (`channel: 'msedge'`), в CI — Chromium. Ждать синхронизацию — `openSynced()`. Упал —
  `npx playwright show-trace test-results/…/trace.zip`.
- **Юнит-тесты интерфейса** — `*.test.tsx` с `// @vitest-environment jsdom` (Testing Library); заглушки jsdom
  и отключённая сеть — `src/test/setup.ts`. Нетривиальная логика (парсеры, сортировки, слияния, раскладки,
  разбивка на страницы, маршруты стрелок) — с маленьким тестом рядом. Тест навигации `App.test.tsx` иногда падает под
  нагрузкой (параллельные сборки), одиночный и в CI проходит.
- **TypeScript строгий:** `strict`, `noUncheckedIndexedAccess`, `noImplicitReturns`, `noUnusedLocals`,
  `noUnusedParameters`. ESLint пока нет: `typescript-eslint` поддерживает TS только до 6.0, у нас 7 — подключить,
  когда выйдет поддержка.
- **Prettier не трогает** (`.prettierignore`) код, перенесённый у группы как есть, — `features/game/hedgehogGame.*`,
  `components/diagrams/arrayCode.js` — наши тесты `src/data/siteQuizzes/` (формат сайта группы) и описания курсов
  `src/data/courseInfo/`.

## Откуда берутся данные

Бэкенда нет. Всё хранится в `localStorage` браузера (zustand `persist`, ключи `m3102:*`, `src/lib/storage.ts`)
и подтягивается синхронизацией `syncGithubContent()` в `src/services/githubContent.ts`:

| Источник | Что берём |
|---|---|
| **RedstoneLord/itmo-m3102** (`REPOS.group`) | дерево файлов (1 запрос к API); конспекты `Конспекты/{Полное_имя_предмета}/{папка}/файл` — папка `Лекция_N`, `Практика_N` или любая своя (`Доп_Материалы`, `Теормины`, `Семинары`, `Таски`, `Тесты`…), на сайте — отдельной папкой; `Дедлайны/deadlines.json`, `data/homework.json`, `data/links.json`, `data/schedule.json`, `data/old-paths.json` (переименованные конспекты), `data/search-index.json` (текст PDF для поиска и «Для ИИ»), `data/memes.json` + `img/memes/`; файлы — с raw.githubusercontent.com (без лимита) |
| **Описания курсов (баллы, преподаватели)** | **лежат у нас**, сайт больше не ходит в Kefirleos/itmo-vault: `src/data/courseInfo/{Предмет}.md` (6 файлов, скопированы оттуда 06.10.2026; подключаются `import.meta.glob`, `buildCourseInfo` в `githubContent.ts`; id записей прежние — `gh:Конспекты/1 семестр/Поток 1/{Предмет}/{Предмет}.md`). Обновить описание — правь файл. Конспекты потока убраны по решению владельца (05.10.2026): в «Конспектах» — только группа; сохранённые раньше стирает миграция `lectureNotesStore` v1 |
| **GitHub Issues** группы | очередь на сдачу (`queue-signup`) |
| `src/data/m3102.ts` | то, чего нет у группы: предметы, студенты (с GitHub), сопоставление папок с предметами, запасное расписание до первой синхронизации |
| `src/data/greetings.ts` | приветствия главной (как `js/greetings.js` у RedstoneLord) |

**Файлы для показа** (PDF, картинки, аудио) берём с `raw.githubusercontent.com` (`rawUrl`/`fileUrl`), **не с GitHub Pages**: Pages
публикует только готовый сайт (`app/site`), конспектов там нет — по адресу `…github.io/itmo-m3102/Конспекты/…` будет 404 (так
сломались PDF после слияния). Минус raw: html-файл показывается текстом, а не страницей.

Публикация в репозиторий группы (ДЗ, мемы) — `src/services/github.ts` (Contents API + PAT пользователя).
Записи из GitHub имеют id `gh:{путь}`; пропавшие из репозитория конспекты архивируются.

**Папка «Материалы» и открытие файлов** (`features/group/RepoFilePage.tsx`, вкладка «Материалы» и `#/files/…`): вкладки «Файлы группы» и корневой страницы репозитория нет (владелец убрал: туда нельзя попасть, `#/files` и папки вне «Материалы/» перекидывают во вкладку «Материалы»; записи лекций и лабораторные остаются в классическом оформлении). Показывается дерево репозитория без служебного: `isHiddenPath` в `groupStore.ts` (с тестом) прячет папки сайта (`js`, `css`, `img`,
`data`, `tools`…) и **все технические файлы в корне** по типу (`.js`, `.css`, `.html`, `.json`, `.webmanifest`,
конфиги, скрытые) — группа добавляет их без предупреждения (так приехали `sw.js` и `manifest.webmanifest`).
Материалы у группы лежат только в папках.

**Профили** (`features/group/StudentProfile.tsx`, `profileStore.ts`) — одно окно на всё приложение: лежит в
`AppShell` (грузится отдельным куском при первом открытии, подписка — в маленьком `LazyStudentProfile`, а не
в самом AppShell), открывается `useProfileStore.open(логин)` — из карточки на «Студентах» (нажимается целиком)
и **из имени в очереди дедлайна** (студент группы — кнопка-профиль, чужой — ссылка на запись). Состояние — своё,
не адрес: смена адреса перерисовывает всё приложение (~100 мс на телефоне), и окно «застывало» при закрытии;
`#/students?u=логин` только открывает профиль по ссылке и сразу убирается из адреса. **«Назад» закрывает профиль**
(а не уводит со страницы под ним): при открытии — запись в истории с тем же адресом, её `popstate` перехватывается
до роутера (`capture` на `window`) и гасится, чтобы роутер не перерисовал приложение; закрыли крестиком/Esc —
запись снимается `history.back()` (`profileStore.ts`). Внутри: шапка — фото 96px

## Стиль кода

- Минимализм: без лишних абстракций и зависимостей; сначала поищи готовый компонент, утилиту или правило в CSS.
  Новая зависимость — только если «несколько строк» не получаются (так взят `modern-screenshot`, а jsPDF — нет).
- Комментарии по-русски, короткие, только «почему», а не «что». Тексты интерфейса — по-русски.
- Анимации — framer-motion (`lib/motion.ts`: `SPRING_SNAPPY`, `SPRING_SMOOTH`) и CSS. «Уменьшить движение»:
  CSS гасит общее правило в `global.css` (длительности → 0,01 мс, поэтому бесконечные анимации надо выключать
  явно — иначе они мигают), framer-motion — `<MotionConfig reducedMotion="user">` в `main.tsx`.
- Стили — CSS Modules на токенах `styles/tokens.css`; глобально — только `global.css` (база, печать, выделение)
  и `aurora.css` (сияние, свечение). Атрибуты состояния на `<html>` (`data-theme`, `data-density`,
  `data-sidebar`, `data-reading`, `data-aurora`…) читаются из модулей через `:global(:root[...])`.
- Нетривиальная логика — с маленьким тестом рядом (`*.test.ts`).

## Решения по темам

### Синхронизация и данные

- **Кеш по sha:** у конспекта `sourceVersion` = `{PARSER_VERSION}:{sha из дерева}`, неизменённый файл не качается.
  Версия ставится, только если git blob sha скачанного совпал (raw кеширует ~5 мин). **Поменял разбор файлов
  (stripFrontMatter, splitTitle, quizPageToMarkdown, папки предметов) — увеличь `PARSER_VERSION`**
  (`githubContent.ts`), иначе старые конспекты останутся разобранными по-старому. Обрезанное дерево
  (`truncated`) — ошибка, а не архивация.
- **Статус** — `services/syncStore.ts` (кнопка в шапке, «Настройки», «Конспекты»). При открытии сайта — сама, не чаще
  раза в 10 минут (`AUTO_SYNC_INTERVAL`; лимит API — 60/час без токена). Защита от двойного запуска — статус
  ставится до первого await. Нет сети → понятный текст и досинхронизация по `online`; лимит → `githubError()`
  пишет время сброса из `X-RateLimit-Reset`.
- **Хранилище:** личное — через `localStore` (`lib/storage.ts`): при нехватке места выбрасывается кеш конспектов
  и описаний курсов (скачаются заново) и запись повторяется; не помогло — предупреждение. Конспекты (~1 МБ) пишутся
  в простое (`idleStorage`). Битый JSON — пустое хранилище, а не падение.
- **Расписание** — из `data/schedule.json` группы (`services/groupSchedule.ts`), до первой синхронизации — из `m3102.ts`.
- **Очередь на сдачу** — issues `[id-дедлайна] текст` с меткой `queue-signup`. Кто стоит — `features/deadlines/queueNames.ts`:
  фамилия студента в тексте (записали друга) → он, иначе GitHub-автор по `M3102_STUDENTS`, «Имя Фамилия». Текст
  заголовка — мелкой припиской, только если в нём что-то сверх имени (уменьшительные — `DIMINUTIVES`).
  Новый студент в группе — добавь его GitHub. Сама страница обновляет очередь не чаще раза в 2 минуты (`QUEUE_TTL`).
  Последняя загруженная очередь сохраняется (`m3102:queue`): лимит GitHub или нет сети — показываем её как есть,
  а внизу страницы мелко «Очередь от 14:32: обновить не вышло — лимит запросов к GitHub, обновится в 15:10».
- **API ИТМО** (my.itmo, БАРС, ITMO.ID) закрыты входом через ITMO ID и CORS — со статического сайта недоступны.
  План сервера (Go, ITMO ID, роли, мемы, очереди) — `docs/BACKEND_PLAN.md`.

### Конспекты, читалка, тесты

- **Совместимость с сайтом группы** (`components/markdown/Markdown.tsx` перед разбором): `:::тип … :::` → выноски,
  `$$x$$` одной строкой → формула по центру, `|` в формулах внутри таблиц → `\vert` (`lib/mathCompat.ts`).

  но не мельче 70% (около 14 px, мельче с телефона не прочитать); если и так шире — горизонтальная прокрутка

### Схемы

- **DSL группы** (`plot`, `graph`, `diagram`, `tree`, `array`, `chart`, `canvas`) рисует свой рендерер
  (`components/diagrams`, синтаксис — README RedstoneLord). У графа `{color: …}`, `{dashed}`, петли, `layout: force`.
- **Стрелки блок-схемы** (`diagram`) — `flowRoutes.ts` (перенос `routeFlow` группы, коммит 375f12e, с тестом):
  S-кривая, если путь свободен, иначе обход по боковой «дорожке» со скруглёнными углами; входы в широкий блок
  разведены, подпись — где нет блоков и линий. Рамка SVG расширяется под дорожки. У обычного графа — прямые и дуги.
- **Код в `array` после `code:`** выполняет интерпретатор группы `arrayCode.js` — перенесён как есть, без eval
  (разбор в дерево, у кода нет доступа к window и localStorage); не править, при обновлении у группы — скопировать
  заново. Шаги показывает `ArrayPlayer.tsx` (фишки ячеек по id переезжают при обмене); для SVG/PNG, печати и PDF
  рядом скрытый кадр (`data-export-frame`).
- **Появление при прокрутке:** фигура схемы проявляется `whileInView` — у недолистанных стоит `opacity: 0`; печать
  и «Скачать PDF» это снимают (см. выше).
- **Редактор схем** (`#/diagrams`, `features/diagrams/DiagramEditorPage.tsx`): источник истины — текст; мышь
  (перетаскивание, «Добавить», «Соединить», «Удалить», инспектор) правит его чистыми функциями
  `diagramEdits.ts` (с тестом), позиции пишутся как `@ x,y`. Отмена — стек текстов (набор склеивается за 700 мс).
  Ctrl+колесо — нативный слушатель с `passive: false` (у React `onWheel` пассивный). Ссылка «Поделиться» —
  `?lang=&src=` (base64url).

### Расписание и календарь

- **Неделя на ПК** — сетка по часам (`WeekView`, раскладка в `weekGrid.ts` с тестом): высота карточки = длительность
  (`--ppm` пикселей на минуту), пары в одно время делят колонку (дорожки), линия «сейчас», у прошедших тише
  содержимое. Воскресенье — только если есть пары. В узком окне планшета сетка листается вбок со snap.
  Подписи часов стоят на линии (`translateY(-50%)`), первая — под линией (в календаре иначе заезжала в «Весь день»).
- **Карточка пары** (`WeekOccurrenceCard`) — карточка на чистой поверхности без обводки и без цветной заливки (цвет типа пары, замешанный в тёмный фон, давал грязно-коричневый — владелец жаловался на это в расписании и ДЗ): тип пары — полоска слева и слово типа. ### Переключатель стиля (общий сайт с двумя оформлениями)

В репозитории лежат **оба** оформления: классическое (статический сайт, корень репозитория) и современное (React, `app/`).
Кнопка «Переключить стиль» — в шапке каждого: у современного в ряду действий (`SiteSwitch.tsx`, залитая акцентом
кнопка), у классического — в ряду кнопок его шапки рядом с GitHub, в его фиолетовом акценте. В интерфейсе слова «мой
стиль» и «федин стиль» не используем и в коде имя человека не пишем: для группы это один сайт, меняется только оформление.

- **Классический сайт лежит в корне репозитория** как в оригинале (список файлов — в «Структуре репозитория»), правок в
  нём нет. Для сайта `npm run classic` (`app/scripts/assemble-classic.ts`) собирает его в `app/public/classic` (не в git):
  копирует файлы из корня и правит только `index.html` (`src/lib/classicPatch.ts`). Источник — RedstoneLord/itmo-m3102,
  `master`; конспекты и PDF он берёт с GitHub по сети.
- **Режимы скрипта** (`app/scripts/assemble-classic.ts`): `npm run classic` — для dev, из корня в `app/public/classic`
  (`npm run dev` делает это сам); `npm run site` — готовый сайт `app/site` (классический в корне + `app/dist` в `/app/` +
  `m3102.ics` в корне: на этот адрес уже подписаны календари); `-- --fresh` к любому из них — самые свежие `data/` и
  `Дедлайны/` с их репозитория (в CI всегда, и раз в сутки по расписанию деплоя: на сайте свежие данные, в git остаётся
  последняя копия); `npm run classic -- --pull` — скачать файлы их сайта с `master` в **корень** (обновить закоммиченную
  копию; коммитить по решению владельца — меняются `data/*.json`). Список файлов — один запрос к GitHub API, файлы — с
  `raw.githubusercontent.com`; без git и без `fs.cpSync` (на Windows оба ломают кириллицу в путях). Лимит анонимного API

- Правки в собранной копии `index.html` только такие (`classicPatch.ts`, с тестом): без манифеста (установка как приложение — за `/app/`), пометка
  `data-site-style="classic"`, подключение `switch/site-switch.js` и **список скрытых файлов его «Материалов» в нижнем
  регистре** (он сравнивает с `base.toLowerCase()`, поэтому «AGENTS.md»/«CLAUDE.md» с заглавными никогда не совпадали и
  показывались как материалы; патч безвредно ничего не делает, если RedstoneLord исправит это у себя). Всё остальное — как в
  оригинале.
- На ширинах 761–1100 px его шапка не помещалась (горизонтальный телефон: поиск и кнопки уезжали за край) — скрипт
  переключателя при монтаже добавляет в классический сайт плотные вкладки и сжатый поиск для этого диапазона (CSS в

### Каркас: меню, шапка, подсказки

- **Шапка** (`TopBar`) — на всю ширину колонки (не по центральной колонке страницы): название раздела сразу
  у боковой панели, кнопки — у правого края.
- **Боковое меню сворачивается** (кнопка в меню, в шапке — когда свёрнуто, `Ctrl+B`; `sidebarCollapsed` в
  `settingsStore`): колонка плавно меняет ширину (переход `grid-template-columns`), меню уезжает влево тем же
  `--sidebar-duration`. Ровные 60 кадров и на конспекте с сотней формул держатся на `useSidebarAttribute`
  (Sidebar.tsx): (1) состояние — атрибут `<html data-sidebar>` и `inert` прямо в DOM, React при переключении
  ничего не перерисовывает (перерисовка меню заставляла framer-motion перемерять всю страницу; обе кнопки всегда
  в разметке, лишнюю прячет CSS); (2) на время анимации разделы конспекта (`[data-lazy-layout] > *`) —
  `content-visibility: auto` с их высотой, раскладываются только видимые; (3) место чтения держится вручную;
  (4) при переключении не меняются наследуемые CSS-переменные — иначе пересчёт стилей всей страницы.
  Хуки в `AppShell` (родитель страницы!) читают стор только нужными полями (`useShallow`), не весь.
  Проверять — частоту кадров на собранном сайте (`vite preview`), dev-сервер шумит.
- **Подсказка к кнопке-иконке** — `components/ui/Tooltip.tsx` (пилюля с клавишами, только CSS: наведение 0,4 с,
  фокус сразу, на сенсорных экранах не показывается; `side="bottom-start"` — у левого края экрана). У кнопки
  внутри — `title={undefined}`, иначе браузер покажет и свою.
- **Нижнее меню на телефоне:** в разделе вне вкладок на месте «Ещё» — его иконка и название.
- **Логотип в шапке** — `src/assets/logo-mask.webp` (600px, 6 КБ), уменьшенная копия логотипа группы
  (`img/icons/logo-t.png` у них); красится маской в цвет текста.
- **Поле даты** — `components/ui/DateInput.tsx`, не `<input type="date">`.
- **Название вкладки** — «М3102 — Раздел» (`lib/useDocumentTitle.ts`): раздел ставит `TopBar` при каждой смене
  адреса, конспект и предмет уточняют своим названием (их эффект срабатывает после шапки — страница в разметке ниже).
- **Модальные окна** (`components/ui/Modal.tsx`) — **не `<dialog>.showModal()`**, а слой через портал в `body`
  (`data-modal`, `--z-modal: 45`: над радио, под меню и подсказками). Модальный dialog делал всю страницу инертной,
  и браузер пересчитывал стили всего документа: ~100 мс на открытии и ~40 мс на закрытии (×4 на телефоне), плюс
  `html:has(dialog[open]) { overflow: hidden }` раскладывал страницу заново — окна дёргались. Не возвращать.
  Сами делаем: прокрутку под окном держим, гася колесо и свайп вне прокручиваемого внутри окна (без `overflow`
  на html); Tab по кругу внутри, Esc и клик по фону — только верхнее окно (стек), при закрытии фокус — обратно.
  Фокус при открытии: в поле — сразу (иначе первые буквы поиска терялись), на кнопку — со следующего кадра (фокус
  пересчитывает раскладку и задерживал появление); если в окне только крестик — на само окно. Меню и календарь
  внутри окна (`DateInput`) рисуются в слой окна (`closest('[data-modal]')`). «Закрывается» — в том же рендере,
  где пришло `open=false` (`mounted && !open`): иначе содержимое на кадр пропадало и пересоздавалось. Анимация —
  только `opacity`/`transform` (композитор): появление 260 мс expo-out (подъём на 8px, scale 0.97), уход 170 мс
  `--ease`; фон без blur (размытие страницы пересчитывалось бы каждый кадр). Окно, которое открывают часто
  (профиль), страница готовит заранее (`prepare()`): первое открытие не ждёт загрузки кода. Проверять — журнал
  событий в странице (касание → вставка окна → `animationstart`) и съёмкой кадров на сборке с CPU ×4.
- **Горячие клавиши** — `features/help/ShortcutsDialog.tsx` (`?`): Ctrl+K — поиск, Ctrl+B — меню; новая клавиша —
  добавь туда же. В полях ввода клавиши-буквы не перехватывать.

### Нажатие, наведение, свечение — как писать

**Главное правило: элемент откликается сам — сдвигом, масштабом, цветом в своих же границах. Никогда не рисовать
поверх него «область нажатия»** (прямоугольник, заливку, вспышку): владелец несколько раз просил это убрать —
выглядит как браузерный дефолт и «видно, где кнопка кончается». Видимая форма элемента и есть его зона нажатия.

**Запрещено** (всё это было на сайте и убрано — не возвращать):

- **волна от клика** (Material ripple, `lib/ripple.ts` — удалён): заливала прямоугольник кнопки или строки;
- **подсветка касания браузера** — выключена `-webkit-tap-highlight-color: transparent` на `html` (`global.css`),
  нигде не переопределять;
- **`:active { background }`** на строках, ссылках, пунктах меню (так было в «Ещё» на телефоне) — на касание
  заливается вся строка. Нажатие — только `transform` самого элемента (ниже);
- **`:hover` без `@media (hover: hover)`** — на телефоне «наведение» залипает после касания, и строка/кнопка
  остаётся подсвеченной на всю область. Любое правило с `:hover` (фон, цвет, рамка, подъём, показ подсказки) —
  только внутри `@media (hover: hover) { … }`; селекторы фокуса (`:focus-visible`) из того же правила — снаружи.
  Так сделано во всех стилях сайта (106 правил, скриптом); новое — пиши сразу так;
- **кольцо фокуса на клик мышью** — только `:focus-visible` (клавиатура), не `:focus`;
- на карточках — свои тени, градиенты, стрелочки «↗», подъём на hover (это «ИИ-кнопка», см. «Свет и плитки»).

**Как надо — по видам элементов:**

| Элемент | Наведение (только мышь) | Нажатие | Фокус с клавиатуры |
|---|---|---|---|
| Кнопка `Button` (primary, secondary, ghost, danger) | фон: `--color-accent-hover` / `--color-bg-hover`; primary и secondary приподнимаются на 2px (framer `whileHover`) | пружина `whileTap scale 0.97` (`SPRING_SNAPPY`) — сама кнопка, без заливок | кольцо `--color-focus` |
| Ссылка в виде кнопки — `<a className={buttonClass('secondary', 'sm')}>` (таблетки GitHub/Telegram в профиле, «Перед контрольной») | как у `Button` (CSS) | без пружины (нет motion) — допустимо, заливок не добавлять | то же кольцо |
| Кнопка-иконка `IconButton` (обязателен `label`) | фон `--color-bg-hover` | `whileTap scale 0.88` | кольцо |
| Карточка / плитка `data-spot` (плитки на главной, карточки студентов, дедлайнов, ссылки на репозитории) | при «Свечении»: рамка загорается за курсором, мягкое пятно света, тень (`aurora.css`); без него — только `border-color: --color-border-hover` | `transform: scale(0.985)` (`global.css`): 80 мс вниз, 320 мс обратно | кольцо цвета акцента |
| Строка списка `ListItem` + `data-row-action` | фон строки `--color-bg-hover` | ничего (переход сразу) | кольцо на действии |
| Чип / таблетка-фильтр (фильтры поиска, имя в очереди) | `border-color` + `--color-bg-hover` | ничего | кольцо; выбранный — `--color-accent-soft` + `--color-accent-text` |
| Текстовая ссылка в подписи («Конспекты», предмет у дедлайна) | `color: --color-accent-text` | ничего | кольцо |

**Зона нажатия = видимая форма.** Растянутый `::after` — только когда визуально нажимается вся строка или карточка
(`data-row-action`, карточка студента). Ссылка внутри карточки — ровно по своему содержимому
(`align-items: flex-start` у колонки), а не на всю ширину. Маленькие цели на телефоне увеличивай размером самого
элемента (кнопки-иконки 40px, строки 64px), а не невидимой зоной вокруг.

**Свечение** («Свечение» в настройках, `data-glow` на `<html>`, `aurora.css`) — только на `data-spot`: рамка за
курсором (`::after` с маской; своя у карточки — `data-spot="own"`), пятно света и тень под курсором,
координаты пишет `appearance.ts`. Только мышь (`@media (hover: hover) and (pointer: fine)`). Новых видов свечения
не придумывать; кнопкам свечение не добавлять (уже есть одно: `primary` при «Свечении» на наведении — светлее сверху и с тенью акцента, `Button.module.css`).

**Ёжик — маскот, а не украшение.** Рисунок — профиль «как эмодзи 🦔» (сплошное тело под иголками, четыре лапки,
улыбка); пробовали круглого ёжика анфас — владелец вернул профиль. Где он есть:

- шапка главной — бегает по дорожке под приветствием, как `.hero-hedgehog` на сайте группы (`HedgehogLane.tsx`:
  сценарий framer-motion — скачет на бегу, задирая нос, 140 px/с, число скачков подогнано под ширину дорожки;
  у края присел, высокий кувырок назад с разворотом в воздухе, пружинка, обратно). Лапки на бегу — плавные качания
  (`alternate` + `ease-in-out`), разворот — `scaleX` через 0 за 0,3 с. По клику — сальто с репликой. «Уменьшить
  движение» — стоит. **Галоп на дорожку не ставить** — владелец просил ускорить только беглеца;
- приветствие «Ёжик вырвался на свободу.» (1 из 37) — вместо дорожки ёжик бегает скачками **по всему экрану**, пока
  открыта главная (`RunawayHedgehog.tsx`): случайные точки не ближе трети экрана, **галопом** (`running="gallop"`:
  ~290 px/с, мах 0,2 с, низкий подскок с наклоном носом вперёд, лапки молотят по кругу — `.gallop` в
  `Hedgehog.module.css`, `gallop()` в `moves.ts`); на месте — то
  сальто, то занос с торможением (`skid`) и короткая передышка; слой
  `pointer-events: none` (нажимается только сам ёжик), рендер через портал в `body` — у страниц на время перехода
  есть `transform`, и `fixed` внутри считался бы от страницы. Скачки и кувырок общие с дорожкой (`moves.ts`);
- засыпает на дорожке, если минуту ничего не трогать (`HedgehogLane.tsx`, `IDLE_MS`): добегает до края, ложится
  (приплюснут), глаза закрыты, над головой плывут «z» (`sleeping` в `Hedgehog.tsx`; глядя влево, буквы
  разворачиваются обратно свойством `scale`). Мышь только откладывает сон — можно подвести курсор и нажать на
  спящего: «Фыр! Я не спал.»; будят клик, клавиша, прокрутка — потягивается и бежит дальше;
- пустые состояния (`EmptyState`, неподвижный); закрыт весь список (`CelebrateHedgehog`, выглядывает из угла
  ~2,5 с вместе с конфетти, мимо него можно кликать; на телефоне — справа, слева радио); индикатор синхронизации;
  игра «Ёжик-кувырок»;
- сезонная деталь (`season.ts` с тестом) — сама по дате, несколько дней в году: шапка Деда Мороза (20.12–10.01),
  тыква (29.10–01.11), шапочка 1 сентября (01–03.09).

Не добавлять: других постоянно скачущих ёжиков, всплывающие окна с ним, ёжика рядом с ошибками и в читалке.

**Ещё про оформление**

- **Шрифты:** Unbounded (`--font-display`) — только главный заголовок страницы, крупные числа и название следующей
  пары; всё остальное — Inter. За каждым — `Inter Fallback` / `Unbounded Fallback` (`tokens.css`): Arial
  с подогнанными `size-adjust` и `ascent/descent-override`, чтобы подмена шрифта не сдвигала вёрстку (CLS).
  Меняешь шрифт — перемерь метрики (ширина текста и `fontBoundingBoxAscent/Descent` против Arial в canvas).
- **Растянутая на строку кнопка** — `position: static`, иначе её `::after` закрывает только текст. Рамка за
  курсором — `::after` у `[data-spot]`; карточке со своим `::after` — `data-spot="own"`.
- **Награда за «сделано»** (`lib/celebrate.ts`): `<Checkbox celebrate>` — искры; `useConfettiWhenCleared(open)` —
  конфетти и событие `m3102:cleared` (на него выглядывает ёжик). Только за вехи, не за каждую отметку.
- **Переход «карточка → страница»** (`lib/morph.ts`, только мышь): ссылка `data-morph`, внутри `[data-morph-title]`,
  цель — h1 с `data-morph-target`. Только у предметов: у конспектов заголовок другого размера и шрифта (1 строка → 3 строки), снимки накладывались друг на друга — для них перехода нет. Внутри View Transition ждать таймерами — `requestAnimationFrame` там не срабатывает.
- **Живой фон** (`liveBg`): `appearance.ts` пишет `--bg-x/--bg-y/--bg-s` на `.aurora`; при чтении конспекта
  сияние гаснет (`data-reading`).
- **Два акцента и динамическая тема** (`settings/appearance.ts`, `tokens.css`): `--accent-base` и `--accent-base-2` — зарегистрированные `@property <color>` (иначе нет плавного перехода; `transition` на `:root`, 1,8 с). Второй акцент по умолчанию — «Роза» (пара индиго → роза), «Авто» = первый, повёрнутый на 45° по оттенку (`oklch(from …)`), либо любой готовый цвет из `ACCENTS`. Градиенты считаются `in oklab` (без серой грязи посередине). Свечение (`aurora.css`) тоже двухцветное: рамка за курсором идёт от первого акцента ко второму, пятно света — два пятна, тень — две, смещённые в стороны; так же у светящегося `primary` и плиток с собственным светом. «Динамическая тема» (`dynamicTheme`: выкл / при запуске / 15 мин / час; «случайно» убрали — лагало, миграция стора v3 заменяет его на 15 мин) каждый раз берёт новую пару `randomPair()` (OKLCH, яркость 0,66, оттенки на 35–90° друг от друга — всегда мягкий градиент), хранит её в `m3102:dynamic-accent` (переживает перезагрузку, пока не вышло время) и перекрывает выбранные акценты; «Сменить сейчас» — событие `SHUFFLE_EVENT`. «Нет» у второго акцента — сплошной цвет (`--accent-base-2: var(--accent-base)`). Пока динамическая тема включена, строки «Акцент» и «Второй акцент» тускнеют и не нажимаются (`SettingsRow lockedNote`, `inert`). Переливания (анимации градиента) нет: пробовали, владельцу не понравилось. «Стекло» (`glass`, по умолчанию выключено, `data-glass` на `<html>`): шапка, меню и нижнее меню полупрозрачные с `backdrop-filter` — дорого на слабых телефонах, поэтому только по галочке. Тёплый акцент (оранжевый/янтарь, `isWarmHue`) совпадал бы с цветом практики — `appearance.ts` ставит `data-practice='deep'`, и практика темнее и бурее (`tokens.css`). Выбранные пункты (меню, список, вкладки, вариант ответа в тесте) — `--accent-soft-gradient`/рамка-градиент; полоса вкладки и ползунок радио — `--accent-gradient`. Новый цветной элемент делай от `--color-accent`/`--accent-gradient`, а не от конкретного цвета. Подсветка и полосы по-прежнему от первого акцента.
- **Радио** в покое тихое: без тени, на телефоне — только кнопка воспроизведения.
- **Тёмная тема** — только на экране (`@media screen` в `tokens.css`): печать и PDF всегда светлые.

## Скорость и загрузка

- Страницы — отдельные куски (`page()` в `App.tsx`), докачиваются в простое и с первого движения мыши/касания.
  Редкие и тяжёлые (дизайн-система, редактор схем) — `page(..., false)`, только по переходу. Модули по кнопке
  («Скачать PDF» — `notePdf.ts` с `modern-screenshot`) — `import()` в обработчике.
- Markdown + KaTeX (~600 КБ) — только там, где нужен: на главной, в описании курса, в форме конспекта и в файлах
  группы — `LazyMarkdown` / `lazy()`. Рисовальщик схем — `lazy` при первой схеме; языки схем — `diagrams/languages.ts`.
  Не импортировать из тяжёлых страниц в лёгкие (так однажды вся страница предмета весила 672 КБ вместо 71).
- Не подписывать на весь стор компоненты-родители страницы (`AppShell`): любая настройка перерисует страницу.
- Поиск (`features/search/searchIndex.ts`) строит индекс один раз и пересобирает при смене данных. Слова запроса —
  в любом порядке (`queryWords` + `hasAllWords`, сниппет — вокруг фразы или самого длинного слова); у схем
  ищутся `title:`/`caption:` и надписи в кавычках, у mermaid и тестов — ничего. Фильтры в окне — тип (название
  группы, `SEARCH_GROUPS`) и предмет (`subjectId` у результата; у дедлайна — `deadlineSubjectId`, у ДЗ и ссылок —
  `resolveSubjectFolder`). Быстрые действия — `searchActions.ts`, совпадение **по началу слов** («тема» не находит
  «математику»); пустой запрос — список общих действий. `#/settings?tab=data` открывает нужную вкладку.
- **Связи** (`features/schedule/lessons.ts` с тестом): номер пары — порядковый среди пар того же вида по предмету
  с начала семестра (без отменённых; семинар = «Практика», лабы не нумеруются), папка конспекта «Лекция 2-3»
  подходит к 2-й и 3-й. Из этого: карточка пары показывает её конспект (`ClassDetailsPopover`), под заголовком
  конспекта — когда была его пара и когда следующая (`NoteLessonInfo`), у дедлайна — предмет, конспекты и папка
  лабораторных (`DeadlineLinks`). «Обзор» предмета — дедлайны и ДЗ группы по предмету (`DeadlinesPanel`
  и `HomeworkPanel` с `subjectId`), конспекты последних занятий, «Мой план».
- Логотипы брендов — свои SVG: `GithubMark` (одноцветный, `currentColor`), `TelegramMark` (как в оригинале:
  голубой круг, белый самолётик). Lucide-иконку `Send` вместо Telegram не ставить — владелец просил оригинальную.
- Ошибки — `components/ui/ErrorBoundary.tsx` вокруг каждой страницы (сбрасывается сменой пути) и всего приложения.
  Устаревший чанк после деплоя — сама перезагрузка, не чаще раза в 30 с.

## Подводные камни

- **Правка файлов скриптом.** На Windows не править TS/CSS/регулярки через Python-, bash-heredoc или `node -e`
  с шаблонными строками: bash съедает обратные кавычки и `${…}`, портятся `\n`, `\d` и слеши. Надёжно — точечная
  замена инструментом редактирования или скрипт из отдельного файла. Файлы в репозитории бывают с CRLF: заменяя
  текст скриптом, учитывай `\r\n`.
- Vite кеширует модули: странные ошибки после правки или смены ветки — перезапусти dev-сервер.
- Строка с многоточием в сетке или флексе: у элемента сетки и у текста во флексе по умолчанию `min-width: auto` —
  длинный текст растягивает строку за край (и дату справа не видно). Нужны `grid-template-columns: minmax(0, 1fr)`
  у сетки и `min-width: 0` у текста.
- Лимит GitHub API — 60 запросов в час на сеть: снимки страниц и Lighthouse по живому сайту быстро его съедают.
  Для проверок подставляй дерево файлов (`gh api "repos/RedstoneLord/itmo-m3102/git/trees/master?recursive=1"`),
  как в `e2e/github.ts`, — свежее, если проверяешь новое у группы.
- Замеры плавности и снимки анимаций — в Playwright (Edge), а не во встроенной панели браузера: свёрнутое окно
  останавливает `requestAnimationFrame`, и анимации «стоят». Для анимаций — `Animation.setPlaybackRate` через CDP.
- Игра «Ёжик-кувырок» (`features/game/hedgehogGame.js`) — код RedstoneLord, перенесён как есть; наши правки
  помечены «Правка поверх оригинала». При обновлении его игры — перенести заново и повторить правки.
- `lib/download.ts` — `saveBlob` / `downloadUrl`: атрибут `download` у ссылок на другой домен браузер игнорирует,
  поэтому чужие файлы качаются через fetch.
- Тестовые данные в `localStorage` для проверок — только допустимые значения типов (`TaskPriority`: low/normal/high/
  critical и т. п.): неверное значение роняет страницу, и это ошибка проверки, а не сайта.
