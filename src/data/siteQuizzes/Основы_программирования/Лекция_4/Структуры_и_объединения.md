title: Проверь себя: структуры и объединения
description: Объявление и инициализация структур, вложенные поля, указатели на структуры, выравнивание и padding, false sharing, union, tagged union и std::variant.

? Какие поля получат `Point first{};` и `Point fourth;` (`struct Point { int x; int y; };`)?
- [x] У `first` нули, у `fourth` неинициализированный «мусор» :: Пустые фигурные скобки инициализируют значениями по умолчанию.
- [ ] Оба будут нулями :: Без `{}` поля локальной переменной не инициализируются.
- [ ] Оба с «мусором» :: `{}` как раз обнуляет `int`.

? Какие инициализации `Point` с designated initializers (C++20) скомпилируются?
- [x] `Point third{.x = 10, .y = 20};` :: Поля в порядке объявления.
- [ ] `Point reversed{.y = 20, .x = 10};` :: Порядок полей нарушен — ошибка компиляции.
- [ ] `Point mixed{10, .y = 20};` :: Нельзя смешивать позиционные и именованные инициализаторы.

? Что эквивалентно `pointer->field`?
- [x] `(*pointer).field` :: Сначала разыменование, потом выбор поля.
- [ ] `*pointer.field` :: Без скобок `.` применяется раньше `*`.
- [ ] `&pointer.field` :: Это адрес, а не значение.

? `struct PoorLayout { char a; std::int64_t b; char c; };` Каков её `sizeof` на типичной 64-битной платформе? Введите число.
= 24
correct: 1 байт `a` + 7 байт padding + 8 байт `b` + 1 байт `c` + 7 байт завершающего padding.
wrong: `b` с выравниванием 8 начинается со смещения 8 (после 7 байт padding), `c` — на смещении 16, а завершающий padding до кратного 8 даёт 24 байта.

? Как уменьшить размер такой структуры?
- [x] Переставить поля: сначала с большим выравниванием (`int64_t b; char a; char c;`) — получится 16 байт :: Padding остаётся только в конце.
- [ ] Никак: размер определяется только набором полей :: Порядок полей влияет на padding.
- [ ] Добавить `alignas(64)` :: Это увеличивает выравнивание и размер.

? Зачем нужен завершающий padding в конце структуры?
- [x] Чтобы в массиве структур каждый элемент начинался с правильно выровненного адреса :: Иначе `b` второго элемента оказался бы не на кратном 8 адресе.
- [ ] Для хранения `'\0'` :: Структуры — не строки.
- [ ] Чтобы ускорить копирование :: Причина в выравнивании элементов массива.

? Что такое false sharing?
- [x] Независимые данные разных потоков попадают в одну кеш-линию и мешают друг другу :: Лечится выравниванием через `alignas`.
- [ ] Два указателя на один объект :: Это просто алиасинг.
- [ ] Чтение неактивного поля `union` :: Это неопределённое поведение, а не false sharing.

? Что правда про `union`?
- [x] Все поля используют одну и ту же область памяти :: Осмысленно только активное поле.
- [x] Чтение неактивного поля обычного `union` — неопределённое поведение :: Нужно помнить, какое поле записано последним.
- [ ] Размер `union` равен сумме размеров полей :: Он не меньше размера наибольшего поля.

? Что даёт `std::variant` по сравнению с tagged union, написанным вручную?
- [x] Тег и активное значение синхронизирует сама библиотека :: В ручном tagged union за это отвечает только программист.
- [ ] Он хранит все альтернативы одновременно :: Хранится одна активная альтернатива.
- [ ] Он работает без проверки типа :: `std::get` с неверным типом бросает исключение.
