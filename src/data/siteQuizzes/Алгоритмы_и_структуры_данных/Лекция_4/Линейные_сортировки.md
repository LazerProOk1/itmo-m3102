title: Проверь себя: сортировка подсчётом и поразрядная
description: Массив-алфавит, префиксные суммы, устойчивость, LSD и MSD, оценки времени.

? Когда применима сортировка подсчётом?
- [x] Элементы — целые числа из известного, не слишком большого диапазона :: Индексы массива-алфавита — это значения элементов.
- [ ] Элементы — любые объекты, которые можно сравнивать :: Подсчёт не сравнивает элементы, а раскладывает по значению ключа.
- [ ] Только если массив уже почти отсортирован :: Порядок входа на сложность не влияет.

? Чем плоха первая версия (просто посчитать вхождения и выписать числа)?
- [x] Она сортирует только сами числа: записи с данными по ключу так не отсортировать :: Из счётчиков можно восстановить числа, но не объекты.
- [ ] Она работает за $O(n^2)$ :: Время у неё тоже линейное.
- [ ] Она требует отсортированного входа :: Нет, вход любой.

? Что хранит префиксная сумма $P[i] = C[0] + \dots + C[i]$?
- [x] Сколько элементов не превышают $i$ — то есть последнюю позицию для значения $i$ в ответе :: По ней элемент ставится сразу на своё место.
- [ ] Сколько раз встречается ровно $i$ :: Это сам счётчик $C[i]$.
- [ ] Индекс первого вхождения $i$ во входном массиве :: Префиксные суммы считаются по значениям, а не по входу.

? Почему исходный массив обходят справа налево?
- [ ] Так быстрее :: Время одинаковое.
- [x] $P[i]$ указывает на место последнего элемента с ключом $i$, и первым его занимает самый правый — порядок равных сохраняется :: Это и даёт устойчивость.
- [ ] Иначе выйдем за границы массива :: Индексы корректны при любом порядке обхода.

? Массив $A = [-3, 5, 0, 5, -1]$. Какой размер алфавита $k$? Введите число.
= 9
correct: $k = \max - \min + 1 = 5 - (-3) + 1 = 9$.
wrong: Нужно покрыть все значения от минимума до максимума: $k = 5 - (-3) + 1 = 9$, а значение $x$ хранится по индексу $x - \min$.

? Какая сложность у сортировки подсчётом ($n$ — размер массива, $k$ — размер алфавита)?
- [ ] $O(n \log n)$ :: Это нижняя граница для сортировок сравнениями, а подсчёт не сравнивает.
- [x] $O(n + k)$ по времени и $O(n + k)$ по памяти :: Выгодно, когда $k = O(n)$.
- [ ] $O(nk)$ :: Проходы по массиву и по алфавиту идут друг за другом, а не вложенно.

? Какое условие обязательно для корректности LSD radix sort?
- [x] Сортировка по каждому разряду должна быть устойчивой :: Иначе порядок, полученный по младшим разрядам, разрушится.
- [ ] Числа должны быть одной длины :: Короткие числа просто дополняются нулями слева.
- [ ] Сортировать по разрядам нужно начиная со старшего :: Это MSD, а LSD начинает с младшего.

? Массив $[170, 45, 75, 90, 802, 24, 2, 66]$ устойчиво отсортировали по разряду единиц. Какое число окажется первым?
- [x] 170 :: Единицы 0 у 170 и 90, а 170 стоял раньше.
- [ ] 90 :: У 90 тоже 0, но в исходном массиве 170 стоит раньше — устойчивая сортировка их не переставит.
- [ ] 2 :: У 2 единицы равны 2, перед ним идут числа с нулём.
explain: После первого прохода: $[170, 90, 802, 2, 24, 45, 75, 66]$.

? Какая сложность у radix sort с $d$ разрядами и алфавитом разряда $k$?
- [x] $O(d(n + k))$ :: $d$ проходов устойчивой сортировки подсчётом по $O(n + k)$.
- [ ] $O(n^d)$ :: Проходы не вложены друг в друга.
- [ ] $O(n \log n)$ :: Radix sort не основан на сравнениях.
