title: Проверь себя: сложность и сортировки
description: Нотации и случаи работы, классы сложности, устойчивость, сортировка слиянием и мастер-теорема.

? Откуда взялась буква $O$ в $O$-нотации?
- [x] От немецкого *Ordnung* — «порядок» :: $O(g(n))$ буквально «порядок $g(n)$».
- [ ] От английского *Operation* :: Нет, обозначение пришло из немецкой математики.
- [ ] От слова *Optimal* :: $O$ — вовсе не про оптимальность.

? Верно ли, что $O$ — это то же самое, что «худший случай»?
- [ ] Да, $O$ всегда описывает худший случай :: Это частая путаница.
- [x] Нет: $O$, $\Omega$, $\Theta$ — вид оценки, а лучший/худший/средний случай — какие входы рассматриваем; понятия независимы :: Можно сказать «в лучшем случае $O(n)$» и «в худшем $\Theta(n^2)$».
explain: Нотация говорит, с какой стороны оценка (сверху, снизу, точно), а случай — на каких данных. Их можно комбинировать.

? Что мы знаем, если про алгоритм известна только оценка $\Omega(n \log n)$?
- [ ] Он работает не дольше $n \log n$ :: Это была бы оценка $O$.
- [x] Он работает не быстрее, чем порядка $n \log n$ :: $\Omega$ — оценка снизу: «не лучше чем».
- [ ] Он работает ровно за $n \log n$ :: Точный порядок даёт только $\Theta$.

? Какие алгоритмы считаются «практически применимыми» по классификации из лекции?
- [x] $O(n \log n)$ :: Растёт чуть быстрее линейной.
- [x] $O(n^3)$ :: Полиномиальная — применима.
- [ ] $O(2^n)$ :: Экспонента быстро становится неподъёмной.
- [ ] $O(n!)$ :: Факториал растёт ещё быстрее экспоненты.
explain: Граница — полиномиальность: $O(n^k)$ при фиксированном $k$ считается практически применимой сложностью.

? Почему сортировка вставками устойчива?
- [ ] Потому что она работает за $O(n^2)$ :: Скорость с устойчивостью не связана.
- [x] Сдвигаются только элементы строго больше `key` (`a[j] > key`, а не `>=`) :: Равные `key` элементы не перепрыгиваются.
- [ ] Потому что она использует временный массив :: Вставки работают на месте.

? Какие три шага у метода «разделяй и властвуй»?
- [x] Разделить задачу на подзадачи того же типа :: Divide.
- [x] Решить подзадачи рекурсивно :: Conquer.
- [x] Объединить решения подзадач :: Combine.
- [ ] Отсортировать вход перед разбиением :: Это не часть метода.

? `merge_sort(a, l, r)` работает с полуоткрытым диапазоном $[l, r)$. Сколько элементов в диапазоне $l = 3$, $r = 8$? Введите число.
= 5
correct: В $[l, r)$ ровно $r - l = 5$ элементов: индексы 3, 4, 5, 6, 7.
wrong: Правая граница не включается: в $[3, 8)$ входят индексы 3, 4, 5, 6, 7 — это $r - l = 5$ элементов.

? Что правда про сортировку слиянием?
- [x] Лучший, худший и средний случаи — все $\Theta(n \log n)$ :: Деление и слияние не зависят от того, как упорядочен вход.
- [x] В стандартной реализации нужна $O(n)$ дополнительной памяти :: Слияние идёт через временный массив.
- [ ] На отсортированном массиве она работает за $O(n)$ :: Так ведёт себя сортировка вставками, а не слиянием.

? Для рекурренты $T(n) = aT(n/b) + f(n)$ с чем сравнивают $f(n)$ в мастер-теореме?
- [ ] С $\log_b n$ :: Это высота дерева рекурсии.
- [x] С $n^{\log_b a}$ — «стоимостью чистой рекурсии» :: Побеждает быстрее растущая из двух функций.
- [ ] С $a \cdot b$ :: Такое произведение в теореме не участвует.
explain: Если быстрее $n^{\log_b a}$ — она и даёт ответ (случай 1), если $f(n)$ — ответ $\Theta(f(n))$ (случай 3), если поровну — добавляется множитель $\log n$ (случай 2).

? Для `merge_sort`: $a = 2$, $b = 2$, $f(n) = \Theta(n)$. Какой случай мастер-теоремы и какой ответ?
- [ ] Случай 1, $\Theta(n)$ :: $f(n)$ не меньше $n^{\log_2 2} = n$.
- [x] Случай 2, $\Theta(n \log n)$ :: $n^{\log_2 2} = n$ совпадает с $f(n)$, добавляется множитель $\log n$.
- [ ] Случай 3, $\Theta(n)$ :: $f(n)$ не растёт быстрее $n$.
